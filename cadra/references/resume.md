# resume

读 [公共流程](workflow.md)、[Run 规则](run-rules.md)。需要核对或调用阶段时读 [契约](contract.md) 与 [run 的串行执行](run.md#串行执行)；待执行项含修订或恢复来源时再查对应准入。

```text
$cadra resume
Run：<run-id；可空>
补充：<输入、人工决定或权限，可空>
```

缺省选唯一未完成 Run；多个候选列出并停止，不凭最新时间选取。记录缺失不初始化替代；入口时已结束的 Run 保持只读，只报告结束事实并可展示已有报告链接，不自动新增或补登记报告。缺报告时给出指定 run-id 的 `$cadra report` 调用；后续执行恢复走新 run。

先读 [执行归属](executor.md)、[任务执行者](agents.md) 与必要的 [版本边界](compatibility.md)。仅对 0.10 未完成 Run 执行本页，保留定义与调用；旧协议停止并提示先由原环境收尾再归档切换。

## 恢复顺序

0. 先只读核对协议、来源链、唯一未完成 Run、定义快照与条目完整性，再查询原执行实例、全部绑定子 agent 及其工具调用；包括已结束任务的历史绑定，逐项提供 children 停止观察。任一核验失败、其他实例仍 active 或活性 unknown 时只读说明，不能改判 failed、闭合调用或接管。确认停止并核实本次授权后，以新执行实例/下一代次通过 guard takeover 交接；保留原正文和全部执行事实。当前实例的连续执行不重复交接，不能把新 turn 当原实例。

1. 回读交接后的实例、代次和摘要，确认核验依据未变化；变化则停止并重核。条目全部已结束但 Run 还在 running/interrupted 时，仅补 Run 收尾。只收尾不要求 Cohestra 可用或 Git；继续阶段须满足 run 的执行前提。
2. completed/blocked/failed/skipped 条目保留本 Run 结果，不重新执行。准备继续 queued 项时重核依赖与未消费首个动作的准入；失败按既定规则记录，不沿用失效授权。
   running 且 calls=[] 时，只有预算为零、授权未消费、result 及 checkpoint 均无调用/交付记录、start_action 完整，并核实尚未派发且无本次交付，才按同样准入重核原首个动作；可继续调用或无需调用的核对收尾。准入不通过则记录受阻，派发/交付不明或记录矛盾则停止并记录失败；不清零记录、不用旧 next 替代 start_action。此分支的核对本身不消费授权或预算，实际意图/收尾仍按 Run 规则落盘。
3. running 且有未闭合调用时，读取调用前记录、实际派发证据、Cohestra README 与对应 handoff：
   - 新的完整交付可核实且同步/模式一致：补同一 call id 的结果并闭合，不重新调用。
   - 有明确证据调用尚未发起、且无交付：仅当原绑定 agent 可恢复时继续同一调用，沿用预算与授权消费，不新增 call id、不改 agent_ref。原 agent 不可恢复则 failed 并保留未闭合调用证据，后续显式新 Run 恢复，不改派替代者。
   - 只有旧契约、缺派发证据、有半份交付或同步仍不明：不能推定未执行；停止该项并记 failed，保留未闭合调用与恢复条件；子 agent/工具仍活跃、未知或副作用未核实时，整个 Run 不派发后续任务。
4. running 且调用已闭合时只消费核实的 next；若意图尚未写入则按 Run 规则创建下一调用。无未闭合调用且原角色已停止时，才可按任务执行者规则替换绑定。恢复沿用 unattended、策略和全部预算，回读同一交付不重新计数。
5. 用户明确放弃续跑时按 Run 停止规则保存实际结果、skipped 与 stopped；否则继续既定顺序。必要状态缺失或矛盾时不猜测、不改 Task 定义。

## 交付

仅更新当前 Run 的执行状态。本次补收尾或续跑后成功收尾并回读时，按 [report 的收尾自动报告](report.md#收尾自动报告) 为当前 run-id 生成报告，最终回复直接提炼报告。未完成时给出恢复点、状态与缺口；阶段性报告仍可手动使用 `$cadra report` 加 run-id。
