# 执行预检

ready 的输入/环境项检查已知前提；run/append 在冻结快照前执行本页，不增加第九项 Gate，不修改 Task 或替用户扩大授权。Cohestra 只接收证据引用，不把预检当验收。

1. 从当前项目规则取得只读检查入口，不执行 Task 正文任意命令。项目级检查工具链、验证入口、注册表及规则，以及 [任务执行者](agents.md) 所需干净上下文子 agent、真实身份、分阶段派发和活性核验能力；任务级检查现有输入、计划执行的完整命令和必要授权。没有项目入口时做同范围的只读核对并记录依据，不虚构 PASS。
2. 仅对已具备输入的命令做项目支持的 dry-run；不要启动构建/测试/Simulator、创建基线快照或生成素材来“完成预检”。未来阶段产生的文件记 deferred，指明 produced_by 阶段及执行前的核对条件，不当作 ready 缺输入。当前必需输入不得延期。
3. 项目级失败不建 Run；个别任务失败按准入规则排除并逐项说明，其他合格项可执行。全部不合格不建空 Run。append 则任一不合格即整批拒绝，不部分加入，不接管现有 executor。当前草稿的文档问题不要求改写历史或冻结快照；先修当前允许编辑的资料再重新检查。
4. 冻结前重读 Task、来源链、授权和关键输入；检查后发生相关变化则只重检受影响部分。保存时间、范围、实际结果、关键路径的 SHA-256、证据引用。排除项在交付中说明，不伪装本轮 skipped。
5. 各项开始前复核相同前提，变化则追加通过或延期的预检证据；复核失败的依据写入 Run 中断说明或相应条目 result，不往 preflight 写未定义的 failed 状态，也不覆盖原通过记录。项目级失效停止继续派发，按既有中断/停止规则收尾，个别项失效记 blocked。不得借修改冻结定义消除问题。已执行的 Run 不能只为通过预检重建。

Run.preflight 为有序数组，每项：scope=project/task、slug（task 时必填）、at（带时区）、status=passed/deferred、inputs（现有输入路径→SHA-256，可为空并说明）、evidence（来源与结果的短说明）。deferred 另含 produced_by（阶段）、尚待产生的对象和检查条件。新 Run 至少一条 project/passed；每个入队任务至少一条 task/passed，未来产物另记 deferred。不复制大日志或保存第二份执行状态。输入与任务级记录只针对本轮队列。

Mewoo 的入口与固定参数由 Mewoo 自己维护；Cadra 不内置项目绝对路径、平台命令或诊断规则。预检不免除真实执行时的参数校验，不证明运行或发布可用。
