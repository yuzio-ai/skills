# add

创建或编辑任务。基础读取仅限公共流程的 [身份与归属](workflow.md#身份与归属)、[共同写入](workflow.md#共同写入)，存储的 [本机容器与忽略](storage.md#本机容器与忽略)，以及 [任务定义](task-definition.md)、[Flow 配置](flow-config.md) 和 [Task 模板](../assets/task.md)。不因链接继续预读 Ready Gate、阶段执行、预算或恢复规则。

```text
$cadra add
任务：<title；编辑时给现有 slug>
需求：<目标、范围、排除项、验收条件>
设计资料：<相关设计稿、文件或链接、已确认结论；可空，已有上下文可直接整理>
优先级：<high / medium / low；缺省 medium>
依赖：<已存在 slug 列表；可空>
流程：<preset 或阶段列表；缺省 code>
执行策略：<stop_queue_on_failure: true/false；缺省 false>
```

## 按条件读取

| 路径 | 读取与处理 |
|---|---|
| 新建 | 确认项目、slug、协议与既有记录；字段、依赖图及配置合法后保存 draft，业务信息不足记缺口，Gate 标注未检查，不填写八项放行结论 |
| 编辑 | 读取当前 Task、目标 slug 的来源链及变更字段；修订与 Gate 失效按任务定义处理，不预先选择重启阶段 |
| 有设计资料 | 新建任务，或本次要求补存／变更设计输入与结论时，按 [设计输入留存](design-inputs.md) 保存相关附件和已确认结论；可直接整理已有上下文。仅编辑无关字段不隐式迁移既有设计输入，未完成 Run 所属 Task 仍不可编辑 |
| 绑定已有交付 | 发现同名索引或正式 handoff 才读 [身份绑定](binding.md)，完成确认后记录来源；不完整的执行材料留给 ready 核对 |
| 旧协议 | 停止编辑或新建替代，按 [版本边界](compatibility.md) 提示先完成归档切换；add 不迁移 |

登记已有认可时保存确认对象／完整方案版本、用户原始答复及可核对来源；区分整体认可、单项决定与代决授权。不能核实的来源标为缺口，不补造消息标识或时间。add 不调用 Cohestra 收敛；已确认但仍保留 blocked 的交接由 ready 按其受限路径核对。

路径可叠加，例如编辑同时绑定已有交付。未知或缺失协议按公共规则停止，不能归入普通新建。

## 查询与保存

普通路径必须按[准备入口](prepare.md)三批完成。先读取目标与归属，再留存并核验附件，最后写前复核、原子发布和回读。依赖只读可达定义图。没有 Task 文件不等于没有历史。只改用户指定字段。不默认调查业务源码、判断依赖是否完成、验证候选或运行构建／测试。绑定变化时重核确认是否仍适用。

只改本 Task、其设计输入附件与必要容器／忽略规则。不执行阶段、不建立 Run、不生成执行总结。最终给绝对路径、slug、preparation、设计资料保存结果、必要缺口与准确下一步。通常为 `$cadra ready` 加 slug。已有 Run 且本次未分代的元数据／等价配置编辑，给 `$cadra list` 加范围 slug。身份或历史缺口未解除时先给对应待办。

普通 add 不创建或改写生成任务的 origin；内部收尾任务仅由来源 Run 的 run/resume 按 [收尾审查](closeout.md) 准备。已结束来源 Run 不重开。
