# 协议边界与本地切换

本包写入、准入与执行仅接受 Cadra Task/Run 协议 `0.11`，继续消费 Cohestra 契约 `0.8`。仅 [list](list.md) 同时支持 `0.10` 原记录的只读查询：按其原有串行状态、快照、预算、角色和来源链核对，不写回、不补齐 0.11 字段、不生成报告或执行建议。其余入口（包括 add/ready/run/append/resume/report）仍拒绝 0.10。缺版本、0.9 及更早版本、未知版本均不接受；不保留旧预设别名、不提供入口内迁移。不能只修改协议号来伪装升级。

list 可同时展示当前容器根目录内独立的 0.10/0.11 记录，明确保留源协议；Run 与自己的定义快照必须同协议，跨协议来源链标 unknown，不拼接成执行依据。多个未完成 Run、缺失或矛盾仍报告。0.10 的 running/interrupted 只表示旧记录状态，活性未知不推荐接管；恢复或收尾交回原环境。查询成功不替代下面的切换要求，不递归读取归档。

本地测试资料切换在技能运行之外一次性完成：先由原执行环境闭合所有未完成 Run，备份容器和安装副本，再原样归档已结束 Run、报告及已完成 Task。归档不参与任务扫描、来源链、状态解析或准入；历史执行事实、身份和验收证据不回填。

仅仍需执行的 Task 进入新容器，保留目标、验收、slug 和 Cohestra 绑定。重新核对绑定和既有交付，记录归档来源与原修订；已执行过的待办建立新修订，旧 Gate 失效，重新 ready。归档前的失败原因未解除不能准入，不借切换重跑已完成任务。

新容器的 Run 来源链从新协议开始，不引用归档 Run 为 `previous_run` 或 `revision_base.run`；切换来源作为 Task 正文中的审计引用保留。需要从既有 Cohestra 交付接续时仍按身份绑定、修订及恢复前提核对，不把“没有新 Run”当作从未执行。

切换前若存在 running/interrupted、未闭合调用、状态矛盾或无法核实的执行，保留原环境；不能为升级接管、停掉或篡改执行。安装副本与资料必须在无运行中批次时同步切换，使用重新加载技能的会话。维护工具不是技能运行依赖。
