# report

读 [公共流程](workflow.md) 与所选 Run；解释异常时再读相应规则，不重新做 Gate、预算或执行判定。

```text
$cadra report
Run：<run-id；可空>
补充：<关注点，可空>
```

未指定时优先唯一未完成 Run；没有未完成 Run 且仅一个 Run 时使用它；其他情况列出候选请用户指定，不凭“最新”猜测。

- 使用该 Run 的结果快照与调用记录，汇总 completed/blocked/failed/skipped；未结束条目另列进行中，不计为失败或跳过。文首注明 Run 状态。
- 每项写状态、最后交付、候选引用、findings 摘要、acceptance、人工介入与下一步。保留 passed/failed/pending/blocked，只有无证据才 unknown。
- 恢复/修订说明来源 Run 与定义 revision。无需调用的收尾明确沿用的候选、验收与原模式，不冒称本轮执行。当前 Task/Cohestra 状态只能单列补充，不能替换旧结果。
- 人工介入集中列出待决定、权限/输入缺口、失败、预算耗尽、协议/模式核对失败与无法确认的调用。正常 flow 边界保留截断范围和实际验收结果。
- 历史 0.6/0.7 只读输出，不登记链接，见 [版本边界](compatibility.md)。0.8 报告另列追加批次、实际角色身份与替换来源、审查方式、覆盖缺口和代码/运行验收边界，引用 Cohestra 证据，不从正文重新决定推进，也不重写旧结果为后续修复结果。
- 新增 `runs/<run-id>-report-<轮次>.md`，回读后经 guard report 在 Run 追加报告链接；链接登记失败不否认报告已生成，后续按准确路径补登记。不得更改原结果。

按 [存储约定](storage.md) 整理必要的正式执行总结。给出报告路径与准确下一步：未完成先按执行归属区分活跃/已停止/未知，仅确认停止且可核对时建议 resume；结束后的失败恢复用显式 run，需求变更用 add/ready。
