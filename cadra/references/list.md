# list

只读查询。读 [公共流程](workflow.md) 与本页；仅在状态异常时查 [Run 规则](run-rules.md)。

```text
$cadra list
范围：<slug 列表或展示状态过滤；缺省全部>
```

容器不存在时报告“未初始化”与目标路径，不写文件。按公共流程解析 Task 定义与关联 Run 的展示状态，再应用范围过滤；分组、排序只影响展示，不改变状态、执行来源或入队顺序。

## 默认展示

有关联 running Run 时按“运行中 Run 队列 → 数量总览 → 其他状态分组任务 → 其他未完成 Run 一览”输出；没有时从数量总览开始。不把所有元数据塞进任务行，也不在底部重复顶部 Run。

- 顶部队列显示 Run 标识、状态、已结束/总项数、当前项及其当前动作；执行者活性未知或异常时保留一句提示。按 Run.tasks 的实际顺序列出查询范围内非 completed 条目，标明状态、title、slug、创建时间及必要异常原因。completed 条目默认只计数；其余条目保留原顺序号，不按状态、priority 或创建时间重排。Run 进度取完整批次，任务数量总览只统计本次查询范围。
- 总览统计本次过滤后的任务总数与各非空状态数量，包含顶部队列任务及默认收起的 completed 项。顶部已列出的任务不在后续状态组重复；各处去重后的任务与收起的 completed 数量必须覆盖总数。已初始化但无匹配项时报告“无匹配任务”，不输出空组。
- 其余任务的分组顺序固定为：进行中 running → 排队中 queued → 阻塞 blocked → 失败 failed → 未知 unknown → 就绪 ready → 草稿 draft → 已完成 completed。每组标明数量，省略空组。completed 默认只显示总数量与“可展开明细”，不逐项列出。
- 用户明确要求“展开已完成任务”、范围筛选 completed、指定已完成任务的 slug 时，展示本次范围内 completed 明细；仍遵循下述创建时间排序，不把展开全部明细作为默认行为。使用自然语言展示要求，不新增数据字段或命令选项。
- 组内按 Task 原始创建时间升序，同一时刻按 slug 字典序。只读取 Task 中明确记录的首次创建时间（包括正文“创建”记录），不把修订或修改时间当作创建时间。
- 时间按实际时刻比较，转换到项目明确指定的时区展示；未指定时使用 Asia/Shanghai，并在总览注明展示时区。日期用 `YYYY-MM-DD HH:mm`，排序保留原始时间精度。
- 创建时间缺失、无法解析、缺少时区或记录相互矛盾时显示“未知”，放在本组有效时间之后，再按 slug 排序。不用文件时间、Run 时间或 slug 推测，不回填历史任务。创建时间未知本身不改变任务展示状态。
- 默认任务行只显示 title、slug、创建时间；blocked/failed/unknown 项另补一句原因或证据缺口，不能因精简隐藏异常。
- 范围明确指定单个 slug 时，在该任务下补充当前 revision、展示状态、priority、依赖状态、flow、当前 Run 与 checkpoint 摘要。多任务查询不逐项展开这些字段。

## 当前动作与角色详情

当前动作是查询时从 Run 记录生成的展示文案，不新增任务状态或持久化字段；它不代替执行者活性判断。

- 当前项的 checkpoint.pending_call 必须能对应同一条未闭合调用，且 stage、dispatch、角色引用与调用证据可核对。prepared 显示“待派发实现/评审/整改/验证”；dispatched 分别显示“实现中/评审中/整改中/验证中”，并注明“已派发，交付待核对”。这些文案仅表示已登记的阶段，不证明工具此刻仍在运行，也不表示交付通过。
- code / review / fix / validate 分别对应实现 / 评审 / 整改 / 验证。旧协议不解析、不作为列表来源；归档不参与扫描。
- 没有未闭合调用时，仅在最近已闭合调用的已核实交付契约明确 next.allowed=true 且 next.stage 合法时显示“等待<对应阶段>”。否则显示“待核对后续动作”。不从 flow 列表顺序、旧阶段名称、时间间隔或聊天描述猜测当前动作。
- pending_call、调用闭合状态、派发证据或阶段记录缺失/冲突时，当前动作显示“未知”及一句缺口，不用另一条较旧调用补位。任务展示状态仍按公共流程解析；发现状态来源本身矛盾时按 unknown 处理。
- 默认隐藏 worker/reviewer 的完整 ID、host/chat/turn/instance 标识。明确要求角色身份、Run 详情、指定 Run 标识或单个 slug 时，再展示范围内实际登记的角色身份和必要核对信息。身份冲突及活性未知等相关缺口仍在默认输出中保留一句提示，收起详情不隐藏异常。

## Run 与后续建议

Run 一览默认只列与查询范围关联的**未完成批次**，按 [Run 状态](run-rules.md#run-状态) 判断：running/interrupted，或 stopped 但仍有 queued/running 项；全部条目已结束的 stopped 属于历史。顶部已展示的 running Run 不重复。历史批次默认不列；用户明确要求“查询历史 Run”时列历史一览，明确指定 Run 标识或要求完整队列时展示该批次的完整任务顺序和旧结果，包括 completed 明细。仅展开已完成 Task 不自动展开历史 Run。

Run 摘要保留总项数、结束项数、当前项及当前动作、追加批次和执行者活性结论；角色完整身份按上述详情规则按需展示。未完成 Run 有多个，或已结束记录存在缺结果、来源矛盾等异常时，必须显式报告，不得因默认收起历史隐藏缺口。Run 一览可按 run-id 倒序，但不能据此决定执行来源。所有队列视图直接取所选 Run 的 tasks 顺序、每项状态及结果，不套用 Task 分组或创建时间排序。旧 Run 的条目始终展示旧结果。

协议不支持、缺来源或结果矛盾时标 unknown 与具体缺口，不补写、不创建队列文件。按 [执行归属](executor.md) 展示活跃/已停止待核对/活性未知；不从 pending_call、prepared 或时间过久推断中断。仅明确已停止且可核对恢复时推荐 resume；活跃或未知保持只读。其余按实际缺口推荐 ready/run/report；已有 running Run 且新任务 ready 时可推荐 append，不将其描述为接管或唤醒。
