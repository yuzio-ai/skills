# 设计输入留存

add 有相关设计资料时读取；ready／预检／派发遇到 Task 中的设计输入时也读取本页。新准备的设计输入应让干净上下文的执行者仅凭任务和保存的附件取得设计依据；既有记录按下方兼容边界读取。不执行设计阶段，不重新要求已给出的确认。

## 适用范围与既有记录

- 新建任务有设计资料，或用户要求补存／变更现有任务的设计输入与结论时，add 执行下方留存规则。仅编辑 title／priority 等无关字段，不因聊天中存在设计资料就隐式修改 requirement 或迁移附件。
- 已有 Task 或 Run 未采用本地留存约定时，ready／run／append／resume 仍按其原 requirement、已记录的输入依据与有效决定核对和传递设计资料；不因缺少新附件目录、三级小节或新采集摘要而拒绝准入／恢复，也不要求先 add。在线来源须实际可读取并符合原记录已有的版本约束与结论；不新增原记录未要求的版本字段或历史证明。原来未固定版本的可变来源应明确其证据边界，不能宣称当前线上稿等同历史稿。必要输入不可读、原有版本约束无法核实或发现影响有效决定的漂移／冲突，仍按既有 Gate／预检规则处理，不豁免实际缺口。
- 已声明留存副本、摘要或留存缺口的输入，按其记录严格核验；文件丢失或摘要不符不能降为旧输入以绕过检查。按实际定义与来源识别，不仅凭目录是否存在、标题或包版本数字判断。
- 未完成 Run 始终使用其冻结定义，不要求补写本地副本或改 Task 才能续跑。若原输入确实失效，按既有中断／恢复规则报告解除条件，不推荐被禁止的 add；只有 Run 按既有授权闭合后，才能在后续 add 中补存或修订。不得为适配新留存规则自动停 Run、改冻结快照或取代在线版本。

## 收集与保存

1. 只整理本任务相关、用户提供或当前上下文已有的设计稿和决定，包括图片、PDF、设计说明、Figma 节点与已有设计交付。编辑时保留未被本次取代的有效资料，不扫描其他聊天或无关目录。没有设计输入的任务不创建空附件目录、不补造设计要求。
2. 将可取得的设计文件独立复制至 `.yuzio/cadra/tasks/<slug>/inputs/<唯一批次>/`；保留格式及必要关联资源。聊天图片使用宿主实际提供的文件／导出能力保存；Figma 等在线稿通过可用连接器导出本任务采用的节点，并保存实现所需的布局、尺寸、状态等说明。原链接保留作溯源，不能代替本地可读副本；截图不能冒充完整可编辑源稿或未提供的交互规格。已有 Cohestra handoff 正文仍只引用，不复制控制记录；其中必要设计文件可独立留存并注明来源。
3. 在 Task 的 `## Requirement` 内以三级小节保存“设计输入”和“已确认设计结论”。逐份记录用途、原始来源／版本或节点、保存路径、实际 SHA-256、采集时间；保存路径以项目根为基准并明确基准，方便 Run 快照和跨目录读取。结论写出具体决定、适用页面／状态、对应稿件及确认来源（消息内容／可取得的标识或已确认文档位置）。只有时间确实可得才填写确认时间。正文保留足够的有效结论，不以“按之前讨论”或仅外链代替。
4. 区分已确认、参考方案、已取代和待决定项。不得把 agent 建议、探索图或用户未确认的细节升级为决定。已有明确取代关系按用户最新决定整理；稿件与结论冲突且取舍不明时保留冲突与缺口，不自行裁决。
5. 附件先写入新的唯一目录，回读核对文件可解码／可读取、内容与来源一致及 SHA-256，再按共同写入规则发布 Task。不得覆盖同名旧批次、原件或其他任务文件，不用符号链接／硬链接替代独立副本。失败时保留可核查现场并报告实际结果，不发布指向未完成副本的成功记录。

缺少下载／导出能力、图片只能查看而无法取得原文件、权限不足或必要资源缺失时，保存已取得内容并在 Requirement 明确缺口；链接不能标成“已保存”。仅当该输入确为必要时阻止后续准入；add 可保存 draft，不虚构附件或已确认结论。能够从现有资料取得时直接完成，不重复索要材料。

## 修订与留存

- 设计稿、采用版本、结论及其引用属于 requirement。改变它们沿用 requirement 的 Gate 失效、changed_fields 和 revision 规则；属于未完成 Run 的任务仍禁止编辑。不得仅替换附件字节以绕过定义修订。
- 已发布的附件批次不可变；更新保存新批次并切换当前 Requirement 的引用。可以复用已核验且内容相同的不可变副本，不因同一 revision 连续编辑就覆盖旧副本。旧 Run 继续读取它冻结的需求及旧附件；不自动采用在线稿最新版本。
- 附件与确认来源属于被引用证据，按 [留存规则](retention.md) 保留；归档和备份包含这些附件及其必要依赖，不因 Task 不再引用就自动删除。本机 `/.yuzio/` 忽略不提供 Git 备份，不能声称已提交或云端备份。

## 准入、冻结与执行读取

- ready 先按适用范围区分既有输入与留存输入；后者在既有“输入／人类决定”项内核对必要设计副本、实际摘要、已确认结论和冲突。无需设计的任务沿用原 Gate。只读核对不替 add 导出或修订需求；需要补存时仅对允许编辑的 Task 指向 add。
- run／append 冻结完整 Requirement（包括已有设计依据、上述三级小节与摘要），不能只摘目标而丢掉设计结论。已留存设计附件用现有任务级 `preflight.inputs` 保存路径→SHA-256，开始／恢复／派发前核对实际字节；缺失或摘要不符时按现有预检失败规则处理，不改冻结定义或悄悄重抓线上新稿。既有输入按兼容边界核对，不追补历史 preflight 或强制建立附件。`.yuzio` 附件不放进禁止该路径的 `ready_scope.inputs`，业务输入指纹仍按原规则维护。
- 派发给 worker／reviewer 时提供冻结的 Requirement 和确认来源；留存输入附副本的可解析绝对路径及摘要，既有输入附其原有效来源／版本及本次读取核验依据。要求实际读取相关图稿与结论后执行，不能只传 Task 路径或主 agent 的概括。恢复和换角色同样传递；review 以相同采用版本核对实现。无需整包重复制进 Cohestra，也不要求执行者读取主聊天。

这些材料是现有 requirement 的必要输入与附件，不新增 Task／Run Front Matter 字段或控制状态，不改变协议 0.12。既有记录保持原输入行为；新留存要求通过允许范围内的 add 引入，不自动迁移或改写历史 Run。
