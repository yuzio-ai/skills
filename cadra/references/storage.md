# 本机资料与正式执行总结

## 本机容器与文档

`.yuzio/` 是当前工作区的本机执行资料。Cadra 的 Task、队列、Run、checkpoint 和报告保存在 `.yuzio/cadra/`，仍是恢复依据，不能视为可随意清除的缓存。Git 不备份未跟踪的本机资料。

首次写入及复用前，检查工作区根 `.gitignore`，最小追加 `/.yuzio/`（已有效覆盖则不重复），保留其他规则并验证生效。容器模板 `.gitignore` 的 `*` 只作防误收兜底。安装和只读 list 不改项目；写入口可维护根忽略规则。已有跟踪文件只报告，不自动移出索引、暂存或提交。项目显式跟踪要求、反向规则、并发或权限冲突保持待处理；未确认忽略生效前不继续写资料。不要用无前导 `/` 的根规则误忽略测试夹具。

根据任务目标、交付用途和适用项目规范判断是否需要正式执行总结；需要时在本入口的交付范围内自动整理，无需用户另行要求“整理文档”或“保存到 docs”。例如任务需要项目交付总结，或项目规范要求保留批次执行报告，就同步更新项目已有文档目录中的相应文档，无约定时用 `docs/` 下合适分类。目录与必要附件可按约定处理时不重复确认；只在缺少影响内容、范围或业务决定的关键信息且无法从现有上下文确定时澄清。只读 `list`、仅讨论和明确不落盘的请求保持原限制；`add`/`ready` 不因此提前生成执行总结。无共享交付需要的 Run 报告留在本机，不机械复制每轮过程记录；正式总结保存范围、结果、遗留、必要证据摘要和稳定引用，不能只依赖 `.yuzio` 或本机绝对路径。不复制队列或 checkpoint 成为第二控制状态源，不把原始日志放进正式文档。Cohestra 负责工程文档与验收记录，Cadra 只交付执行总结；写文档不等于提交或发布。
