# 新 Run 显式恢复

run 的恢复列表只接受当前展示状态 blocked/failed，必须包含于显式 slug 范围，不能和“全部 ready”组合。原 Run 必须结束，项目无其他未完成 Run。来源链与 Gate 的核对见 [公共流程](workflow.md)、[准入](task-rules.md)。

## 恢复准入

1. 读取链尾与按 [公共流程](workflow.md) 确定的执行依据，核对解除失败/受阻的事实、本次补充及既有授权，包括首调用前受阻的条目。缺记录、原因未解除或状态矛盾时保持原状，不入队。
2. 首调用前受阻且可证尚未派发、无对应交付时，重新核准原 start_action；有定义修订时先按 [修订规则](revision-rules.md) 累计变更并选择起点，不能用旧 completed 交付替代未执行的新需求。原调用未闭合或同步失败时，对照调用前记录、README 和 handoff 核实交付：完整交付不重跑，仅明确未发起且无交付才沿用原待调用动作；半份交付或派发不明不能推定未调用。核对结论写新 Run，不改旧 Run。
3. 已交付且终态映射为 completed 时，作恢复核对收尾，不调用阶段。否则，合法 next 允许且位于 flow 内时正常续接；旧结果仍为 blocked/failed 且 stage_result 同为 blocked/failed 时，原因解除、阶段与原 checkpoint 一致且在 flow 内，才允许恢复重试该阶段一次。
4. 无合法动作（例如必做阶段仍在 flow 外）时说明缺口；不清除 Cohestra blocked、不伪造 next、不从正文猜阶段。

恢复通过后在新 Run 保存来源与首个动作。一次恢复授权只提供一个起点，与首次调用意图或无需调用的核对收尾结果同写已消费；之后只消费新契约。新 Run 有自身预算，resume 不重置同一 Run 的预算。

若此前恢复项在任何调用/收尾前被 skipped，展示状态为 ready，但不能作为普通任务绕过本页准入。用户此次显式 slug 选择才构成重新恢复选择，不要求把 ready 写入恢复列表；“全部 ready”跳过此类任务并说明。每次核对重新取得解除证据，不自动复用旧授权。
