# Task 准入与 Ready Gate

## 定义与编辑

定义、字段校验、Gate 失效和修订分代仅由 [任务定义](task-definition.md) 规定，准入复核定义时读取该参考；flow 配置见 [配置规则](flow-config.md)。add 不读取下方准入表。

入队排序按 priority 高到低，同级按 slug 字典序；依赖未完成的任务不进入同一 Run，依赖链逐层推进。append 仅排序新增批次后整体放到尾部，不按新优先级重排原队列。仅接受协议 0.10；旧记录停止准入并提示先归档切换，详见 [版本边界](compatibility.md)。

## Ready Gate

以下八项是唯一准入定义。ready 逐项记录结论和依据；run 的普通、恢复、修订候选及 append 批次均复核，开始/续跑前另重核依赖。复核不是隐式调用 ready，也不修改 Task。

| 检查 | 通过条件 |
|---|---|
| 目标 | 可判定的目标，不是待探索的方向 |
| 范围 | 做什么、不做什么清楚 |
| 验收 | 完成现象与验收条件可判定 |
| 人类决定 | 无待裁决的产品取舍或缺失授权 |
| 输入 | 必要输入、参考与环境前提齐备；按 [预检](preflight.md) 检查当前前提，未来阶段产物另列 |
| 依赖 | 所有依赖的当前定义展示状态均为 completed |
| 起点 | flow start 合法；接续/恢复/修订的首个动作可核对 |
| 范围配置 | flow 按起点与允许集合解释，配置有效 |

ready 只适用于展示状态 draft/ready：通过时 preparation=ready；未通过时 preparation=draft。旧 Gate 记录保留；同一定义重复通过不重复追加等价放行记录。其他状态先按恢复或修订入口处理，不靠 ready 重开终态。只有该修订已通过 Gate 且此次复核通过，才可进入 Run。

已有交付或 Run 执行依据时，起点项按 [完整契约与前置检查](contract.md#前置检查与首个动作) 核对候选适用性、控制字段及合法首动作；定义变更时按 [重启准入](revision-rules.md) 核对。add 的身份绑定不替代上述检查，缺口未解除不得放行。
