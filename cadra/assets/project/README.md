## 使用

在智能体中使用 `$cadra add`、`ready`、`list`、`run`、`resume` 或 `report`，后附任务描述、任务 slug、run-id 及本次补充。目标项目尚无本目录时，技能会先提醒并执行一次最小初始化，再继续该入口。其他工具使用各自的技能调用写法。

- [tasks/](tasks/)：每个任务一个文件，保存任务定义、Ready Gate 结果与运行记录。
- [queue/](queue/)：`order.md` 保存队列清单（列定义与旧版升级规则见文件内模板）——序号、入队时间、消费 Run、入队操作编号与出队操作编号及结论；旧版七列清单保留原表块、新入队记录写入追加的八列表块，未出队的旧行就地补写其既有结论单元格；文件不存在表示尚无队列记录。
- [runs/](runs/)：每次 Run 一个文件（含 checkpoint 与逐任务执行记录），报告为 `<run-id>-report-<轮次>.md`。
- 本目录保存多任务执行和调度状态；单任务流程与工程证据在 `.cohestra`，通过 `cohestra_task: .cohestra/handoffs/<task-slug>/` 引用关联，不把 handoff 内容复制进来。
- 规则与入口提示词保存在技能包中，不在此复制。业务规范仍归项目所有；任务决定、执行状态与恢复依据按 tasks/ 与 runs/ 追溯。
- 普通入口只写自己的交付物与队列清单，不反复更新本入口。每轮落盘记录实际采用的技能发行版本，历史文件不随技能升级重写。
- 目录已初始化后复用，不按执行工具重复创建；同一项目同时至多一个未完成 Run。
- run 建立新 Run，blocked/failed 用显式范围与恢复列表重新入队；resume 只续未完成 Run。恢复不改旧 Run 结果，定义编辑前必须收尾所属未完成 Run。终态任务的定义修订回 draft、重新 Gate 后按修订重启入队（不写进恢复列表），旧 Run 结论与新旧定义分别保留。
