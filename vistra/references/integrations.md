# 现有 Skill 协作协议

按需加载。独立 Vistra 任务不要求 Cohestra、Cadra 或 Relatra 已安装、初始化或执行。

## 职责与目录

| 所有者 | 职责 | Vistra 边界 |
|---|---|---|
| Cadra | 准备、队列、顺序、Run、恢复 | 沿用其 Cohestra 调用控制契约，不直接消费视觉完成度推进队列 |
| Cohestra | 工程阶段、任务交付、正式验证 | 可在 design 使用探索/比较/交接，在 review/validate 使用专项评审；Vistra 不写工程状态 |
| Vistra | 发现、视觉候选、选择依据、交接 | 默认写 `.yuzio/vistra`，返回准确产物引用 |
| Relatra | 事实采集、目标归并与周期报告 | 接入适配后只读证据，非每次设计的必经步骤 |

`.yuzio` 是项目资料根目录，不是 Skill 安装路径。未来 `.yuzio/cohestra`、`.yuzio/cadra`、`.yuzio/relatra` 仍由各 Skill 拥有。当前其他 Skill 保持原路径，Vistra 可以引用其旧资料，不迁移、双写、初始化或升级它们，也不声称它们已支持新路径。

## 调用输入

调用方通过宿主传递可获得的信息，不增加 CLI/RPC：目标项目、父任务、对象与范围；模式及顺序、领域、预期交付；规范、品牌、基线、候选；冻结与可变项；有效选择与授权来源；预算、执行限制、输出位置。

调用方已确定预算优先于 Vistra 默认。Cohestra design 已确定一套代表图时，不扩成三套。上层未授权的外发、运行、写入或实现动作不能由子调用补齐。无人值守调用继承其限制，遇到需要人工决定且无代选授权时返回缺口，不空等、不代选产品方向。

## 返回与消费

以 [报告骨架](../assets/report.template.md) 返回实际包版本、产物契约版本、准确入口、请求与实际模式、领域、逐模式状态、四个结果维度、选择依据、证据限制和剩余前提。v0.1 是可读交接协议，不声称存在自动解析器。

调用方应核对对象、候选、版本、图片可读性和缺口。产物不存在、版本无法解释或请求部分未完成，不能按成功继续。Vistra 的 `completed` 仅表示静态视觉专项交付完成，不是工程任务 `completed`、`acceptance` 或 `next` 指令。HTML、交互原型及运行验证由工程流程承接，不作为本 Skill 的执行步骤。

Cohestra 依据自己的阶段契约发布控制状态，Cadra 只消费该控制契约。Vistra 不改其他 Skill 的 README、索引、队列、验收或问题关闭记录。上层引用 Vistra 产物即可，不复制另一套任务索引。

## 审查、报告与过渡

工程 review/validate 调用应记录执行者、与候选作者的关系及实际检查范围。作者自检不能冒充独立审查；概念图不能替代所需运行、交互或无障碍验证。Vistra 结果不降低父任务验收要求。

Relatra 按独立目标与证据归并，不以图片、候选、报告数计成果。成本只用可观察值。当前自动采集器对 `.yuzio/vistra` 的支持留待后续升级并验证；过渡使用明确产物引用与既有证据机制，不改其采集脚本。

项目专用 UI/UX Skill 保留在项目。迁移其方法依赖必须是明确授权的项目变更，不能随 Vistra 安装自动修改。局部/整页/概念等内部分类映射为探索范围，不替代四种模式；尚未迁移的 Taste 引用在报告中说明兼容缺口。

后续统一迁移需覆盖路径解析、模板、历史引用、恢复与报告采集，不以搬目录替代验证。
