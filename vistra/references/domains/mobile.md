# mobile · 移动端

用于触控界面、页面关系、手机与平板场景。先辨认视口、输入方式、用途、导航和项目容器约束。通用视觉语言可跨系统；安全区、返回入口、键盘、原生控件及辅助技术要求以项目为准，不从操作系统标签推导一套新皮肤。

## 设计方法

- **任务顺序**：确定用户先看到的信息、下一步动作及次要管理操作。用分组、字重、间距和位置表达顺序，不把所有内容变成同等权重的卡片或标签。
- **空间分配**：在同样内容下比较列表、分组区段、主次区域或媒体比例。密度由任务决定；重要长文本允许扩展，不能为留白删除事实。
- **跨屏连续性**：同一方向固定颜色角色、字体层级、间距节奏、组件家族、媒体处理与导航含义。不同页面可有不同构图，但状态与内容应能沿实际路径衔接。
- **媒介与材质**：只有助于理解内容、品牌或任务时使用图像、纹理和装饰。保留项目既有图标与原生组件，不因上游风格偏好替换。
- **差异设计**：布局探索可分别尝试信息优先、动作优先、媒体优先，前提是符合本轮目标；它们是可选思路，不是固定三模板。每个候选应能说明结构变化的收益和代价。

阅读、日常工具和开放概念的表现目标分别判断。阅读任务让真实正文与媒体关系形成节奏；工具页面以信息和操作为主；开放概念可探索更强的图像或字形表达。既有插画、照片、头像和图标按真实角色保留，不能为统一风格重画用户内容。原始品牌资源的显示尺度、裁切及颜色处理要与引用一起核对。

## 生成与检查

移动画面默认为原始页面，不加手机外框、透视或手持场景。展示包装仅在请求需要时添加，并与页面证据区分。多屏请求按真实路径规划代表屏，不自动扩为整套应用。

领域简报在 [explore](../modes/explore.md) 公共字段上补充：屏幕用途、入口/返回/主动作、内容密度、系统区域、文本扩张、键盘或浮层影响、跨屏固定规则。平台未定时可探索内容区，受影响的容器约束保留待决。

| 检查对象 | 观察重点 |
|---|---|
| 内容层级 | 标题、主信息、时间/来源、管理动作是否容易区分 |
| 触控与导航 | 主要动作、返回、滚动与浮层关系是否合理；不能从概念图宣称触控已验证 |
| 文本与适配 | 长名称、多行、文本放大、窄视口时的策略；不靠缩字、删字段维持布局 |
| 状态与媒体 | 加载、空、错误、禁用等本轮相关状态；媒体裁切不损害内容身份 |
| 跨屏一致性 | 同一候选内的品牌、组件、字段语义与导航连贯性 |

状态语义按 [约束核对](../constraints.md) 检查。图中系统栏、Tab 或控件外壳若为示意，说明参照范围，不作为原生验证。
