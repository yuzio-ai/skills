# desktop · 桌面端

覆盖浏览器、原生应用和混合容器的桌面场景。先识别产品工具、营销、内容或紧凑辅助窗口；不能把所有桌面任务套成营销首屏或三栏工作台。视口、输入方式、窗口和容器限制来自目标项目。

## 按用途设计

| 用途 | 设计决策与比较重点 |
|---|---|
| 产品、工作台、编辑器 | 明确当前对象、主要任务和状态；比较列表/详情、分区、操作位置与信息密度；保留表格、表单、批量操作和错误反馈的必要复杂度 |
| 营销、品牌页面 | 组织主张、依据与行动；选择符合内容的构图、媒介比例和段落节奏；事实、评价与数据必须有来源，不为画面添加虚假证明 |
| 内容、编辑型页面 | 保持阅读顺序、行长、标题层级和媒介关系；导航服务定位，装饰不干扰阅读 |
| 紧凑面板、设置、辅助窗口 | 保留有限空间内的核心任务、上下文和退出方式；不强加主窗口布局或无关导航 |

营销页面探索或评审时，说明每个主要区段回答什么用户问题、如何支持下一步行动，识别重复或缺少依据的论述。AIDA（注意、兴趣、欲望、行动）仅作可选分析框架，不固定区块数量、顺序、组件或留白，也不据此编造事实。产品工具、内容页面和紧凑面板沿用各自任务标准，不套营销结构。

构图选择应能解释内容关系。可比较居中、偏置、分栏、整幅媒介或紧凑标题结构；不固定左文右图，也不禁用它。方向差异来自目标所需的结构变化，不能只换材质和强调色。

营销和品牌首屏按 [艺术指导](../art-direction.md) 形成概念、主视觉与阅读路径。视觉隐喻属于提案，不能由道具或概念场景引申出虚构产品能力、发布状态或链接。

产品工具可比较列表/详情、筛选、密度和状态关系，无需套用营销主视觉。不同数据粒度与规模的比较按 [约束核对](../constraints.md) 限定范围。

多区域或长页使用统一品牌、字体层级、组件与行动语义，允许区域规模和节奏变化。代表图、整页或局部图按比较问题与预算选择；不强制“每区块一张横图”，不默认六张或八张。

## 交互与呈现

关注鼠标、键盘、选择、焦点、窗口缩放和区域间关系。小窗口不等于移动端；需要触控适配时补实际约束。图中 hover、焦点、错误或可拖动提示只能说明意图，真实行为仍需运行证据。

任务相关标题栏、工具栏和窗口关系可以保留；它们不等同装饰性的设备外框。默认不添加无关桌面背景。缩小截图不能作为可读性改善的证据。

领域简报补充：用途、视口范围、主要操作、信息密度、区域关系、允许变化的构图、窗口/焦点/选择状态、内容与媒体来源。营销图与工具界面不能互换评判目标。

## 评审与交接

- 查主要任务是否清楚、次要动作是否抢占层级、表格和表单是否保留字段与状态；不能用空白区域掩盖未设计流程。
- 查文本扩张、空/加载/错误、长列表或内容溢出的策略；对未执行的适配和键盘行为写待验证。
- 映射现有布局容器、组件、Token、最小/扩展尺寸策略和焦点顺序。具体系统菜单、快捷键与窗口 API 由项目工程处理。
- 营销交接保留真实内容顺序、媒介需求和行动目标；图片中虚构的数字、字体或功能不成为产品事实。
