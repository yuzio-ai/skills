# 本机资料与正式设计交付

`.yuzio/` 是当前工作区的本机执行资料。`.yuzio/vistra/` 保存本机 profile、探索候选、评审和选择记录；被采用的原图与不可再生证据仍须保留，不能因忽略就视为缓存。团队设计规范和共享默认值保留在项目已有真源，profile 引用它们，不成为唯一共享配置。

首次落盘及复用前，若目标在 Git 工作区，检查根 `.gitignore` 并最小追加 `/.yuzio/`（已有效覆盖则不重复），保留其他规则、回读并检查实际生效。只读请求和技能安装不改项目；非 Git 目录不创建 Git 配置。已有跟踪只报告，不自动移出索引、暂存或提交；显式跟踪要求、反向规则、并发或权限冲突待处理，忽略未生效前不继续写本机资料。规则只匹配工作区根，保留嵌套测试夹具。

## 本机产物

默认 `.yuzio/vistra/artifacts/<任务标识>/`，用户或调用方明确输出位置优先。复用上游任务标识；独立任务按对象与目标命名。首次落盘只建所需 Vistra 目录，不创建其他 Skill 容器或强制 profile；已有稳定产物直接引用。编号与候选保留规则见 [证据规则](evidence.md#报告引用与保留)。

## 正式交付

根据任务目标、交付用途和适用项目规范判断是否需要正式设计说明、评审报告或设计交接，需要时自动整理有效内容和必要素材，不等待用户另行要求“整理文档”或“保存到 docs”。例如要交给开发、任务要求形成可实施设计，或项目规范要求保留设计评审结论，均按对应模式的职责完成文档。优先更新项目已有文档/设计资源目录中的相应文档，无约定时使用 `docs/design/<任务标识>/`；必要附件与引用一起补齐。

沿用已有选择，不重复请求批准。目录与附件可按约定确定时直接处理；只有关键设计决定或交付范围无法从现有上下文确定时才澄清。普通探索、过程评审及本机比较留在 `.yuzio`；仅记录选择、仅讨论、纯只读或明确不落盘的请求不自动扩展。需要持久交付的草案可按任务/项目要求进入文档目录，但必须保留草案、未决和未验证标记，不能通过整理替用户选择方向。

正式说明包含准确候选版本、采用范围、有效决定、组件/Token/品牌映射、限制和待验证项；所需图片放在文档资源目录或稳定可访问的明确位置。正文和必要附件不能只链接 `.yuzio`、临时路径或本机绝对路径。正式文档成为共享交付真源，本机记录指向其路径与版本；不机械复制全部探索轮次、提示词或日志，不发布新共享规范，不把概念图称为可用生产素材或工程验收证据。无法持久交付时保留已有本机结果并说明缺口。
