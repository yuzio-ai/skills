# 证据、结果与产物契约

正式报告与跨 Skill 交付沿用产物契约 `1`，包版本从实际加载的 [release.json](../release.json) 读取。契约是可读报告的字段语义，不是队列控制状态或自动解析 API。普通对话无需读取版本文件或套用完整报告。

维护时，报告必需字段或结果语义的变化须评估产物契约兼容性；配置解释方式的变化按 [profile 格式](profile.md) 单独评估。旧报告与候选保留生成时的版本和引用，不通过改写版本号伪装为新格式；包版本更新不表示已安装或发布。

## 交付用途

- **普通对话与本机过程记录**：直接使用所请求模式的交付内容，不强制输出包版本、契约版本、作者关系、四个结果维度或无关的“未执行”。必须给判断依据，明确影响结论的未知、未完成部分及候选版本歧义；未实际查看或验证的事项不能暗示通过。
- **正式报告、正式设计交接、跨 Skill 返回**：保留实际版本与作者关系、请求范围与实际模式、领域、准确来源与候选、判断依据和限制、四个结果维度；组合调用按模式说明实际范围及缺口。使用 [公共骨架](../assets/report.template.md) 组织，不逐栏填表。作者自检不能冒充独立审查。

按任务用途和项目要求确定，不以“是否落盘”单独判断：本机探索记录可简短，明确要求正式评审报告则需完整追溯。正式内容已保存时，对话只给主要结论、限制和入口，不复制全文。仅记录选择不自动扩展为完整交接。

## 证据能力

本轮视觉产物为静态图片。运行截图、交互和无障碍结果仅可引用用户或上游已提供的证据，标明执行主体与来源；Vistra 不启动页面、浏览器或模拟器来生成运行证据。保留这些类别用于解释已有材料，不表示本 Skill 提供相应执行能力。

| 类别 | 可支持的判断 | 不能单独证明 |
|---|---|---|
| `specification` | 规则、范围、预期 | 当前实现符合 |
| `concept-image` | 视觉方向、内容关系、概念可读性 | 精确字体指标、真实交互、正式无障碍结果 |
| `runtime-capture` | 指定版本、尺寸和状态的显示 | 其他状态、尺寸或辅助技术表现 |
| `source-inspection` | 组件、Token、布局策略与结构 | 实际渲染正确 |
| `runtime-interaction` | 已执行路径的行为 | 未执行路径通过 |
| `accessibility-check` | 实际检查项目及结果 | 整体无障碍认证 |
| `asset-inspection` | 已检查素材的格式、参数、字体和变体 | 未检查的可编辑性、使用条件或应用效果 |

每项证据记录类别、准确来源、对象或候选、观察、限制。图片尺寸、语言、外观和状态按实际信息填写；引用已有运行截图时保留其已知环境、构建和捕获时间，缺失为未知。概念图不填造设备、系统或构建记录，不把提示中的视口当作实际运行尺寸。

概念图与真实截图可以比较设计关系，但证据类别不同不能直接证明实现质量改善。没有实际查看图像时，记录未查看，不仅凭生成完成消息声称视觉自检通过。

## 问题与选择

普通评审给出发现、位置与依据、影响、建议和必要限制，区分确定问题、待核实项与可选建议。正式报告中的问题另保留稳定 ID、严重度和验证方法；复审沿用旧 ID 与来源，区分原问题、新回归和未核实风险。

沿用项目严重度。缺省为 Blocker（事实、权限、关键内容、主要操作或必要结构严重破坏）、Major（重要层级、可读性、主要动作、一致性或适配明显受损）、Minor（局部节奏、对齐或细节）。审美偏好不能抵消 Blocker；未知不能凭空变为通过或失败。

选择记录保留决定、主体、来源、范围和准确候选；选择与授权的路由按 [入口](../SKILL.md#路由)。局部修订只更新受影响部分，新决定写明覆盖关系；候选变化后先核对选择对应的版本。没有可读取记录时写“本轮未能确认”，不能断言用户从未选择。

## 区域差异与采用范围

多区域预览、组合候选或继承前轮内容时，用简短差异表说明：区域、本轮实际变化、来源及准确修订、采用依据或尚未确认的范围。区分本轮新增/调整、沿用已选、暂作参照、仅位置联动；这些是说明用语，不是新增任务状态。单一区域且无继承歧义时用一句话即可，不强制填表。

例如“入口 D-r01 + 暂作参照的摘要 A-r01”不能只标成“D 整页”。局部采用不自动覆盖参照区域；结合当前请求和有效上下文核实交接范围，仍不明确时仅将受影响部分列为待决。用户已明确采用可定位的整页组合时记录整页选择，不要求逐区域重复确认。对话至少点明影响理解的参照或联动，不能只藏在完整报告中。

## 四个结果维度

| 维度 | 内容 |
|---|---|
| 交付完成度 | `completed` 请求交付齐备；`partial` 已交付部分且仍有缺口；`blocked` 关键前提缺失，无法形成请求的实质交付 |
| 设计判断 | 发现、取舍、推荐、可继续讨论范围及不确定性 |
| 方向选择 | 未能确认有效选择 / 用户选择 / 授权代选；候选与依据 |
| 实现验证 | 默认未执行；如引用上游既有证据，注明执行主体、范围、结果和限制 |

正式组合交付逐模式说明状态、实际范围和缺口，可用短列表；尚未开始的模式注明未开始，不伪造执行。全部请求交付完成才能给总体 `completed`。评审发现 Blocker 仍可完成评审交付；完整交接不表示实现通过。单项检查区分通过、失败、未运行、环境受阻。

设计判断按 [约束依据](constraints.md) 和 [艺术指导](art-direction.md) 分开评价符合性与视觉质量。review/compare 可以完成并发现全部候选不合格；explore 请求合格方案却只交违规稿时，仍有交付缺口。

引用既有交互证据时区分审阅界面与产品行为，不把上游执行写成本轮实测。修订记录分开保留首稿偏差、最终偏差与未验证项；图片数和修订后的通过不能抹去首次偏差，也不证明未展示条件通过。跨 Skill 的条件未统一时限定结论，不把交付方式或媒介差异直接当成设计能力优劣。

## 报告、引用与保留

依上文交付用途选择短段落、列表或表格。公共字段只在本文件定义，各模式定义其交付内容；不逐项填“无／不适用”。涉及候选、映射、决定或资源时保留下表相关语义，可合并表达，不要求独立栏目。

后续轮次只写本轮变化、受影响候选/决定、新证据与剩余缺口，准确引用可读取的上轮报告及未变上下文。当前候选修订、选择范围、结论与限制仍须明确；引用失效或内容改变时补足相关信息。交付前移除未使用栏目并替换实际采用部分的占位符。

| 记录 | 必填语义 |
|---|---|
| 候选 | 报告内简称、准确产物引用、修订或版本、证据类别、可获得显示条件 |
| 组件映射 | 界面角色、现有组件或 Token、来源、采用方式、缺口或新增提案 |
| 品牌映射 | 元素、选定来源、用途、已确认参数、待制作或验证项 |
| 决定 | 内容、主体、来源、范围、候选及覆盖关系 |
| 资源 | 实际图片数、修订轮次、工具结果与可观测成本；未知时间或 token 不估填 |

简称 A/B/C 只在报告内有效。后续引用报告、候选、修订与真实路径；可获得哈希或稳定版本时附上用于核对。不能让“采用 B”漂移到同名的新图。

缺省文件名 `vistra-review-01.md`、`vistra-explore-01.md`、`vistra-review-explore-02.md`；概念图如 `concept-B-r01.png`，真实画面如 `runtime-baseline-01.png`。扩展名匹配文件格式。写入前检查冲突，选择未占用编号；新轮次保存新产物并引用旧轮次，不覆盖已被选择或交接引用的文件。可稳定访问的原素材直接引用，不强制复制。

本机报告按工作区解析，正式交付按 [存储约定](storage.md) 整理必要说明和素材，不以本机目录作为唯一依据。报告内优先用相对路径，注明相对基点；对话给可打开的准确入口。外部引用失效或持久产物写入失败时不宣称交付成功。保存后重读关键字段、链接及选择版本。

没有正式报告需要时，不为保存完整证据另写报告。公开包与测试只保留通用或虚构数据。
