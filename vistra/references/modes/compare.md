# compare · 候选比较

输入至少两个可定位候选和比较目标。当前版本可作为候选；未生成、不可读或损坏的文件不能凑数。

1. 固定候选的准确来源、修订和证据类别，核对内容、语言、尺寸、外观、状态。参考 [候选规则](../evidence.md)。
2. 根据用户目标和领域选标准。按 [约束核对](../constraints.md) 说明候选符合性与关键未知，再按 [艺术指导](../art-direction.md) 比较效率、可读性、品牌与表现。违反必须保留项的候选不作为满足约束的方案推荐；关键证据未知时限定建议。固定权重或评分不是必需。
3. 同一标准逐项比较，指出不可比条件。内容量或尺寸不同只比较仍成立的维度；概念与运行证据不能混成实现改进结论。
4. 给出推荐、关键理由和最强反对理由。允许保留当前、全部不合格或证据不足无法选优。

约束符合性、视觉质量与资源投入分别说明，按本轮目标取舍，不默认合成总分。多方案、报告详尽或检查数量都不能抵消视觉薄弱。不同示例、尺寸、方向数或预算限制比较结论。静态画面可比较构图和状态表达，不能据此评价交互效果或响应布局；生产效率与品牌偏好需要相应证据。

用 [compare 正文](../../assets/modes/compare.section.md) 交付清单、可比性、差异、取舍和缺口。候选不足时不静默换模式、不捏造第二版；可整理前提，受影响的比较保持未完成。

推荐后结束，不把推荐记为选择。已有有效选择要如实记录，不强迫用户重选；明确委托代选则按委托范围记录主体与依据。后续“就用 B”等选择语句按 [入口路由](../../SKILL.md#路由) 处理；用户要求交接且选择门槛满足时继续 handoff，明确不交接的限制优先。
