# handoff · 设计交接

输入：选定方向、选择来源、准确候选版本、范围和可读项目规范。普通跟进延续已确定事项。

1. 核实选择与当前候选一致。组合预览按 [区域差异规则](../evidence.md#区域差异与采用范围) 核对各区域来源及采用范围，不能把暂作参照的区域自动并入局部选择。无有效选择时整理共同约束及草案；不得代选。明确委托“你选一版并交接”时可在委托范围内选，记录为授权代选。
2. 把已确认决定、实施建议、新增提案、待决事项分开。实质偏离已选方向且不在已有授权内时，需要新的明确授权，不能用新的设计依据替代；已授权局部修订无需重新确认全部方案。
3. 按下方方法拆解选定设计并映射：界面用现有组件、Token、布局、文本弹性、导航和相关状态；品牌用 Logo/字标、颜色、字体、图形语言与应用规则。读取对应领域要求，不为局部任务强行展开全套。
4. 列实现前提、未制作素材、未验证行为和验证方法。新增组件/Token 只作提案，不直接发布为共享规范。

## 从选定设计到可执行描述

先用一句话写清本轮视觉意图和需要保留的关键关系，例如“正文是首要信息，时间与来源依次降低层级”。定位到准确候选的区域或元素，再按相关维度拆解，不能只写“高级、简洁、有呼吸感”。

存在主视觉时，保留其概念、主体尺度、叠压/纵深、文字与图像关系、材质和裁切，以及相关视口的重排意图。将准确文案、Logo/Signature 和其他素材分别映射，区分原资产、生成概念与待制作资源。不能在组件映射时静默移除主视觉、压平构图或替换为通用栅格；确有实现或约束冲突时说明损失和待决部分。

| 维度 | 交接内容 |
|---|---|
| 布局与间距 | 阅读与操作顺序、分区和对齐、内外间距关系、主次比例、容器层级；固定与弹性区域、内容扩张/溢出及相关视口下的重排策略。不把某张图的宽度直接当通用断点 |
| 排版 | 文本语义角色、字级与字重关系、行高、宽度及换行/截断策略；映射字体样式或 Token。涉及字体身份、语言覆盖或字重可用性时引用可核实材料 |
| 色彩与表面 | 语义名称、功能用途、外观/状态及对应 Token；需要明确值时附色彩空间、单位和来源。说明边界、圆角、阴影或透明度承担的层级作用，不只列色板 |
| 组件与导航 | 界面角色、现有组件及变体、主次动作、图标与标签、导航或容器关系。说明哪些属性复用、哪些是局部覆盖或新提案；与已选设计不一致时列差异，不静默换成通用模板 |
| 图像与品牌素材 | 准确资产及修订、用途、裁切/比例、显示范围和可用变体；素材来源及已核实的使用条件。区分概念图中的示意与可交付原素材，列出字体、图标或母版等待制作项 |
| 状态与动效 | 本轮相关状态的触发条件、反馈、恢复与退出；已有动效或提案的目的、触发、起止关系和减少动态效果策略。入场显现、滚动驱动、固定或叠放应说明回退后的排列及内容、操作如何保持完整可达，不依赖动画完成；必要时恢复普通排列。图中悬停/按压暗示只作意图，不能写成已验证行为 |

每项用“语义用途 + 视觉关系 + 现有资源映射 + 参数依据”描述；现有资源按任务选择组件、Token 或品牌素材，能复用的值优先引用真源。精确值注明依据类型：项目规范/源码、可核实资产参数、实际测量，或待确认提案；同时给单位与适用条件。截图像素不能直接冒充平台布局单位。无需测量的关系可保持关系描述，不为填表捏造数字。

例如：正文映射项目的主要文本样式，时间映射辅助样式并位于正文之后；准确字号从对应样式读取。若候选只展示了两者的相对大小，就交接该关系，字号保持待核实，不把猜测写成字体名称或已确认 Token。

## 缺口与一致性核对

- 选择已确定与交接材料齐备分别核对。仅有候选代号或区域清单、没有可核对的设计内容，或必要组件/Token/素材映射整体未知时，可以交付选择与关系草案，但 handoff 保持 partial。不得因整页选择齐备而称完整交接，也不能将这些必要缺口全部推给工程阶段。用户明确只要求选择或来源摘要时可完成该限定交付，说明它不是完整设计交接。
- 内容先与已确认文案和产品事实核对；生成图额外的功能、数据或承诺不能因候选被选中而自动成为事实。不可辨内容标未知，不能补成产品决定。
- 沿用 [约束核对](../constraints.md) 的有效记录，复查本轮受影响的图片与来源；图片中的操作仅为设计意图。行为不因已选方向而变为已验证，约束冲突与审美取舍分别交接。
- 细节不清时先查现有规范、组件和原素材，再用现有候选中实际可辨的关系交接。仍缺关键决定时给草案与最小待决项；可选建议单列。补图或新方向属于另行明确的探索，沿用已有预算，不为交接自动重生成。
- 按实际范围核对内容顺序、层级、间距关系、组件家族和媒介处理是否保持已选方向；跨区域/跨端引用同一候选的准确修订及相应规则。必要映射与项目约束冲突时列出影响与待决部分，不能借“实现方便”改换方向。

## 交付与停止

用 [handoff 正文](../../assets/modes/handoff.section.md) 交付。拆解维度可按任务合并或省略，不要求另建 `DESIGN.md` 或发布新规范。关键决定及本轮必要材料、映射齐备才能称完整交接；布局/品牌或必要目标约束仍缺失时为草案，明确受阻部分。非关键参数可作为提案或待验证项，不强求所有数值已测量，也不重复确认已有选择。不要从位图推造字体名称、精确尺寸、矢量母版或运行结果。

交接完成后停止。产物可以指导后续工程，但不能自动修改生产代码、写工程状态、关闭上游问题或宣布正式验收。实现授权和验证范围依 [证据规则](../evidence.md) 独立记录。
