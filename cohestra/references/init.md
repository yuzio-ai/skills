# init

在目标 Git 工作区建立最小 `.yuzio/cohestra` 上下文容器。同时按 [存储约定](storage.md) 维护项目根 `/.yuzio/` 忽略规则；只处理容器和项目入口，不读业务任务全文、不运行阶段、不安装或升级技能。

显式 init 与阶段自动初始化使用同一最小范围：建立或复用容器与项目入口，不提供旧格式迁移或清理流程。既有文件保留；状态缺口按公共流程处理。

## 定位与写入

1. 固定用户指定或当前任务项目的绝对路径；从子目录定位 Git 工作区根目录。非 Git 目录或目标不明确时报告，不能把技能源仓库当成目标，也不自行执行 git init。
2. 读取适用项目规则和必要目录状态，确认只有一个初始化执行者。阶段文件、业务文件和既有用户改动均保持原样。
3. 新项目只从本技能的 [项目入口模板](../assets/project/README.md) 与 [忽略规则](../assets/project/.gitignore) 建立下面的结构。入口模板填入实际项目名称和本次 [发行版本](../release.json)；未知信息说明未确认，不捏造。

```text
.yuzio/cohestra/
├── README.md
├── .gitignore
├── handoffs/
│   └── .gitkeep
└── retrospectives/
    └── .gitkeep
```

4. 磁盘无容器、但 Git 仍有该路径时（删除未提交，或历史中存在），先报告再建立：可恢复的跟踪文件清单（含数量与内容版本）与不可恢复的未跟踪项；跟踪记录与本次新建之间的差异——是否提交删除、是否先取回——由用户决定，init 不暂存、不提交、不 checkout，也不把新建表述为已迁移。
5. 已有容器直接复用：只补缺失文件和目录，不覆盖 README、忽略规则或记录，不因发行版本变化重写入口。按存储约定最小维护项目根忽略规则；已有容器内规则保留，不把只忽略 scratch 当作整体忽略已完成。两个记录目录仅在新建或为空时补 `.gitkeep`。
6. 遇到同名普通文件阻挡目录、指向外部的上下文链接、并发变化或写入权限问题时报告准确路径；不删除、替换或绕过。创建前重查目标，写入后回读。中途失败说明已创建内容和未完成项，不宣称自动回滚。

## 由普通阶段触发的初始化

其他阶段在目标项目没有 `.yuzio/cohestra` 时，按最小范围先执行一次 init 再继续本阶段：

1. 范围只到容器可用：建立或补全目录、项目入口、忽略规则与两个记录容器。不读业务任务、不清旧副本、不生成任务、不暂存或提交。
2. 先向用户说明目标绝对路径与「将执行一次初始化」，再执行；目标不明确、有多个候选或指向技能源仓库时先澄清，不在错误目录初始化。
3. 完成后回到被中断的阶段继续执行，并在该阶段交付物的「身份与输入」中写明本轮发生过初始化。

## 完成检查与交付

- 新布局不包含 prompts 或模板管理 manifest；不会复制整份技能包、自动创建任务或历史交付。
- 不同工具访问当前项目时复用同一容器，按现有索引和交付记录继续，不按工具创建副本。
- 报告目标仓库、创建/复用/受阻结果、实际写入路径及缺口，给出 `.yuzio/cohestra/README.md` 的绝对路径。磁盘无容器但 Git 仍有记录时，另附可恢复与不可恢复清单，并标明本次新建与 Git 记录的差异。
- 下一步可用 `$cohestra need` 加原始需求，或从实际需要的阶段直接起步（例如已定位的缺陷用 `$cohestra fix`）；初始化结束后停止。
