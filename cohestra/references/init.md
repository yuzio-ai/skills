# init

在目标 Git 工作区建立最小 `.cohestra` 上下文容器。只处理目录和项目入口，不读业务任务全文、不运行阶段、不安装或升级技能。

## 定位与写入

1. 固定用户指定或当前任务项目的绝对路径；从子目录定位 Git 工作区根目录，worktree 使用自身根目录。非 Git 目录或目标不明确时报告，不能把技能源仓库当成目标，也不自行执行 git init。
2. 读取适用项目规则和必要目录状态，确认只有一个初始化执行者。阶段文件、业务文件和既有用户改动均保持原样。
3. 新项目只从本技能的 [项目入口模板](../assets/project/README.md) 与 [忽略规则](../assets/project/.gitignore) 建立下面的结构。入口模板填入实际项目名称和本次 [发行版本](../release.json)；未知信息说明未确认，不捏造。

```text
.cohestra/
├── README.md
├── .gitignore
├── handoffs/
│   └── .gitkeep
└── retrospectives/
    └── .gitkeep
```

4. 已有容器直接复用：只补缺失文件和目录，不覆盖 README、忽略规则或记录，不因发行版本变化重写入口。已有忽略规则未覆盖任务 scratch 时报告；只有用户已授权合并该规则才最小追加。两个记录目录仅在新建或为空时补 `.gitkeep`。
5. 遇到同名普通文件阻挡目录、指向外部的上下文链接、并发变化或写入权限问题时报告准确路径；不删除、替换或绕过。创建前重查目标，写入后回读。中途失败说明已创建内容和未完成项，不宣称自动回滚。

## 旧目录兼容

旧项目可能仍有 `.cohestra/prompts`、`manifest.json`，或在 README 中保存了完整协议。init 不删除这些文件，不刷新旧校验值，不批量重写交付。

如果旧入口声称项目提示词仍是唯一有效来源，在本次明确的 init 指派内，仅在 README 增加一段来源说明：新的 `$cohestra <阶段>` 派发采用实际加载技能内的规则；旧提示词是历史引用，项目业务约束与任务已确认决定仍有效。保留原文和记录；README 写入前重读，若发现业务约束冲突或无法安全区分则报告待处理，不宣称完成迁移。重复 init 不重复追加这段说明。

彻底清理旧流程副本需另行明确范围，先检查是否有项目定制和历史引用。init 的兼容说明不代表旧文件已清理，也不创建新的协议副本。

## 完成检查与交付

- 新布局不包含 prompts 或模板管理 manifest；不会复制整份技能包、自动创建任务或历史交付。
- 两个工具访问同一工作区时复用同一容器；不同 worktree 通过 Git 同步文件，不承诺即时共享。
- 报告目标仓库、创建/复用/受阻结果、实际写入路径、旧目录兼容情况及缺口，给出 `.cohestra/README.md` 的绝对路径。
- 下一步可用 `$cohestra need` 加原始需求，或明确派发 `$cohestra quick` 修复；初始化结束后停止。
