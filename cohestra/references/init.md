# init

在目标 Git 工作区建立最小 `.cohestra` 上下文容器。只处理目录和项目入口，不读业务任务全文、不运行阶段、不安装或升级技能。

本技能有两种执行范围：**最小初始化**由普通阶段在容器缺失时触发，只建容器与项目入口；**完整 init** 由用户显式指派，在建立容器之外还处理旧目录兼容与授权内清理。两者边界见下文各节，不互相借用。

## 定位与写入

1. 固定用户指定或当前任务项目的绝对路径；从子目录定位 Git 工作区根目录，worktree 使用自身根目录。非 Git 目录或目标不明确时报告，不能把技能源仓库当成目标，也不自行执行 git init。
2. 读取适用项目规则和必要目录状态，确认只有一个初始化执行者。阶段文件、业务文件和既有用户改动均保持原样。
3. 新项目只从本技能的 [项目入口模板](../assets/project/README.md) 与 [忽略规则](../assets/project/.gitignore) 建立下面的结构。入口模板填入实际项目名称和本次 [发行版本](../release.json)；未知信息说明未确认，不捏造。

```text
.cohestra/
├── README.md
├── .gitignore
├── handoffs/
│   └── .gitkeep
└── retrospectives/
    └── .gitkeep
```

4. 磁盘无容器、但 Git 仍有该路径时（删除未提交，或历史中存在），先报告再建立：可恢复的跟踪文件清单（含数量与内容版本）与不可恢复的未跟踪项；跟踪记录与本次新建之间的差异——是否提交删除、是否先取回——由用户决定，init 不暂存、不提交、不 checkout，也不把新建表述为已迁移。
5. 已有容器直接复用：只补缺失文件和目录，不覆盖 README、忽略规则或记录，不因发行版本变化重写入口。已有忽略规则未覆盖任务 scratch 时报告；只有用户已授权合并该规则才最小追加。两个记录目录仅在新建或为空时补 `.gitkeep`。
6. 遇到同名普通文件阻挡目录、指向外部的上下文链接、并发变化或写入权限问题时报告准确路径；不删除、替换或绕过。创建前重查目标，写入后回读。中途失败说明已创建内容和未完成项，不宣称自动回滚。

## 由普通阶段触发的初始化

其他阶段在目标项目没有 `.cohestra` 时，按最小范围先执行一次 init 再继续本阶段：

1. 范围只到容器可用：建立或补全目录、项目入口、忽略规则与两个记录容器。不读业务任务、不清旧副本、不生成任务、不暂存或提交。
2. 先向用户说明目标绝对路径与「将执行一次初始化」，再执行；目标不明确、有多个候选或指向技能源仓库时先澄清，不在错误目录初始化。
3. 完成后回到被中断的阶段继续执行，并在该阶段交付物的「身份与输入」中写明本轮发生过初始化。
4. 需要旧目录兼容或清理时另行指派完整 init（见下两节），不借最小初始化顺手处理。

## 旧目录兼容

旧项目可能仍有 `.cohestra/prompts`、`manifest.json`，或在 README 中保存了完整协议。init 不删除这些文件，不刷新旧校验值，不批量重写交付。

如果旧入口声称项目提示词仍是唯一有效来源，在本次明确的 init 指派内，仅在 README 增加一段来源说明：新的 `$cohestra <阶段>` 派发采用实际加载技能内的规则；旧提示词是历史引用，项目业务约束与任务已确认决定仍有效。保留原文和记录；README 写入前重读，若发现业务约束冲突或无法安全区分则报告待处理，不宣称完成迁移。重复 init 不重复追加这段说明。

彻底清理旧流程副本需另行明确范围，先检查是否有项目定制和历史引用。init 的兼容说明不代表旧文件已清理，也不创建新的协议副本。

### 授权内的清理

默认不清理。仅当用户在本轮 init 指派内给出明确范围时，才对范围内的旧流程副本执行下列步骤；范围外一律保留并报告。README 中保存的完整协议副本属于旧流程副本，可按同一流程收敛为[项目入口模板](../assets/project/README.md)口径的入口。

1. **判据：定制还是漂移**。逐份比对项目副本与技能 `references/*.md`。差异只涉及标题、版本字样、章节划分、派发方式等结构变化，判为版本漂移：无项目定制，可清理。出现业务词、项目路径或项目本地约定，判为项目定制：保留并报告，不清理。
2. **混合内容文件不适用上述判据**。项目入口常同时保存流程副本与项目专属事实（项目名、任务索引、各任务验收状态、本地约定）。按下列顺序收敛：先提取项目专属事实清单并逐项列出；以[项目入口模板](../assets/project/README.md)为骨架重建，流程章节按骨架重述，不搬运原文；重建后逐项对照清单核对，任一项缺失即报告未完成；替换前先按安全动作备份原文。
3. **引用盘点**。清理前全仓检索待清理路径，分两类说明处置。可变索引与项目入口可改指向技能入口；已交付阶段文件按「已交付不可改写」保留悬挂记录，不回改。先说明会产生哪些悬挂引用再动手。
4. **安全动作**。先复制到仓库外并逐项对平文件数，确认无遗漏后再移入系统废纸篓。不使用不可恢复的直接删除。备份位置与还原方式写入本轮报告。
5. **校验**。改动后回读磁盘内容；对改过的文件检查相对链接是否仍可解析；确认忽略规则仍覆盖任务 `scratch/`。
6. **边界**。只清旧流程副本与规则上可丢弃的产物。任务记录（`handoffs/`、`retrospectives/`）不因「已完成」而删除：只有整体验收通过且用户明确要求时才处理；验收未通过时先报告前提，交由用户决定。
7. **不顺手做的事**。不重写已交付文件、不补造历史交付、不刷新旧校验值、不扩到业务文件或共享契约。清理结果与未清理项分别报告；只完成检查时写明已检查、尚未清理。

## 完成检查与交付

- 新布局不包含 prompts 或模板管理 manifest；不会复制整份技能包、自动创建任务或历史交付。
- 两个工具访问同一工作区时复用同一容器；不同 worktree 通过 Git 同步文件，不承诺即时共享。
- 报告目标仓库、创建/复用/受阻结果、实际写入路径、旧目录兼容情况及缺口，给出 `.cohestra/README.md` 的绝对路径。磁盘无容器但 Git 仍有记录时，另附可恢复与不可恢复清单，并标明本次新建与 Git 记录的差异。
- 下一步可用 `$cohestra need` 加原始需求，或从实际需要的阶段直接起步（例如已定位的缺陷用 `$cohestra fix`）；初始化结束后停止。
