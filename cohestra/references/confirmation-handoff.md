# 确认后的阶段交接

need/design 收到整体认可、明确免除整体确认，或由 Cadra ready 请求补齐确认交接时读取。确认是否充分仍按 [共用澄清规则](clarification.md) 判断；本页不新增阶段、入口或契约字段。

## 正常收敛

- 接续当前 need/design 的确认答复是本阶段工作的继续。确认适用于当前完整汇总且必要关键决定已齐备时，先完成本阶段 handoff、校验和索引发布，再交给用户指定的下一入口；不只在聊天中致谢或把确认留在 Cadra Task 正文。
- 记录被确认的完整汇总／交付版本、用户答复与可核对来源，以及适用范围。已有同一确认可复用，不重复提问；来源无法核实、内容实质变化或仍有关键决定时，不推定确认成立。
- 原 blocked 交付保留；确认使本阶段首次具备完成条件时，新增本阶段下一轮交付。若已有同一内容的有效完成交付和同步成功的索引，直接复用，不为重复请求新增轮次。
- 若有效 handoff 已完成而索引同步失败，按 [发布恢复](publication.md#恢复) 核实并同步原轮次，不把发布重试当作新阶段。同步成功并回读之前不交给下一入口。
- 用户只要求当前阶段时，仍按既有终点语义交付；阶段完成和实施授权分开。确认不启动下一阶段、实现、构建、Simulator 或 Run。用户明确要求先完成交接再执行 Cadra add/ready 时，先结束本阶段交接；独立调用 Cadra add 仍只登记资料，由 ready 按下节补齐。

## Cadra ready 的受限请求

这属于入队前的 attended 准备，不是 Run 的 unattended 阶段派发。由当前主会话按 Cohestra 规则执行本阶段收敛，不要求创建子 agent，不伪造 Run、call id 或编排角色。

请求须带目标项目、同一任务目录、待收敛的 need/design、当前完整方案及既有确认来源，并明确只补齐交接。Cohestra 独立核对身份、当前输入、确认适用性、关键决定和终点；Cadra 的“已确认”标签本身不是用户认可的证据。

- 仅补齐被确认的当前阶段，不调查并开展新的需求／设计工作，不修改业务实现或 Cadra Task/Run。need 完成后仍需 design 时交回人工，不代做 design。
- 本路径只允许写该任务必要的 handoff 和索引；若必须修改正式项目材料才能完成交接，报告该独立调用前提，不以准备请求扩大写范围。
- 保留用户明确指定的“仅设计”等终点。不能因 Task.flow=code 或 ready 调用把 task_completed 改为 next=code；有新的明确范围指令时由独立阶段调用登记，不在此路径推定。
- 复用、新增轮次和索引恢复沿用上节；通过 [发布流程](publication.md) 写入并回读。遇到并发变化、写入所有权不明或不充分确认时停止，报告真实缺口；不覆盖旧交付或降低门禁。

交接结果说明实际任务、阶段／轮次、交付路径、索引同步结果、剩余前提及允许的下一步。只发布既有契约 0.8 字段；准备请求来源写正文，不增设控制字段。
