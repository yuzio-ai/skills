# report

通过 $cohestra report 调用。此入口只查询已有任务记录，不是工程阶段，也不执行 review、verify 或 validate。

## 调用与范围

```text
$cohestra report
```

默认汇总当前项目 `.cohestra/handoffs/` 下全部任务，包括已完成、受阻和失败任务。其他项目可明确指定：

```text
$cohestra report
项目：<目标项目绝对路径>
```

先固定目标项目并读取适用项目规则；目标不随技能安装位置变化。多个项目无法区分时先澄清，不扫描其他项目或用户会话。缺 `.cohestra` 时报告「未初始化」并停止，不运行 init；缺 handoffs 目录时报告记录缺失，不等同零任务。已存在且可完整读取的空 handoffs 目录报告「暂无任务」。

## 只读边界

- 只枚举目录、读取索引及必要来源，在对话中输出；不创建目录、缓存、报告文件、handoff 或临时索引，不修改任何项目文件。
- 不迁移旧任务、不修复索引、不回填字段，不改变任务状态、findings 计数、延期裁决或关闭规则；不登记 report 轮次，也不写机器契约。
- 不执行测试、构建、审查、整改、验收、阶段推进、提醒或调度。只呈现已记录的推荐下一步，其存在不产生执行授权。attended / unattended 均适用以上边界。

## 读取与判定

1. 枚举 handoffs 下每个任务目录，先读各自 README。缺失或不可读的 README 仍在总览保留该目录，状态写「未知」并列异常。松散旧交付、无法归属的文件与目录读取失败列为覆盖缺口，不凭文件名补造任务；不递归遍历 scratch、备份、复盘或业务源码。
2. 有合法且支持的 Front Matter 时，以它为当前控制状态来源；`stage_result` 表示最近正式阶段交付，不代表正在执行。README 正文仅补充任务名称、负责人和必要链接。字段语义按 [公共流程](workflow.md) 第 7 节解释；可选 findings / acceptance 缺失是合法的，但显示「未知」，不转换为零、通过或已关闭。任务 completed 不推导验收 passed。
3. 无 Front Matter 的旧任务，可展示正文明确记载的状态并标注「正文记录／无契约」；缺项写「未知」。已有 Front Matter 但 YAML 无法解析、契约不支持或必填字段不合法时，标注「契约异常」，相关当前状态写「未知」，不以正文或历史 handoff 冒充有效控制状态。
4. 按各任务索引定位有效 review findings、fix 裁决及必要的后续复审来源；支持旧版合并交付中的对应章节。只读必要来源，不预读全部阶段历史。不能仅凭文件编号最大、修改时间最新或未被索引确认的交付替换有效输入。索引指向草稿、来源缺失或有效关系不明时，列缺口，不自行裁决。
5. 按「任务目录 + finding ID」合并原问题与后续处置，不跨任务合并同名 ID。已明确关闭的问题不重复列为遗留；接受判断、延后、转交或仅写「已修改」不自行推导为已关闭，修复与复审状态按记录分别展示。已有不接受裁决的条目按原裁决展示，不重新打开；处置是否终结不明确时标「待核实」。无 ID 的旧问题用来源位置区分，不生成或回写新 ID。
6. 每个任务都核对索引中的问题来源，不能因任务 completed 或计数为零／缺失就跳过遗留项。Front Matter 计数与问题明细不符、正文与控制字段冲突、同一 ID 裁决互相矛盾时，保留各自来源并列入状态异常，不覆盖记录或重算后冒充正式计数。未能确认关闭的历史问题写「待核实」，不擅自宣称仍未关闭或已经关闭。
7. 报告反映本次读取到的记录，不证明业务当前正确、审查独立或验收证据仍适用。读取过程中发现记录变化时，重读受影响索引和来源；仍不稳定则标「读取期间变化」，不宣称整份报告是同一时点的原子快照。部分读取失败时输出其余可读结果并标「覆盖不完整」。

## 输出与停止

开头注明目标项目绝对路径、报告时间及时区、任务目录总数与成功读取数；概括已记录的任务状态分布和异常数。未知、正文记录与覆盖缺口单列，不混入已确认的结构化状态计数；findings 汇总有缺项时只报已知数与未知任务数，不给出伪完整总数。

### 任务总览

| 任务（链接 README；缺失时链接目录） | 最近阶段／轮次及阶段结果 | 任务状态 | 验收状态 | 未关闭阻塞／非阻塞／待核实数 | 已记录的推荐下一步 |
|---|---|---|---|---|---|

每个任务一行，任务名不能代替目录身份。默认全部展示，按受阻／失败、进行中、已完成分组，未知或异常单列；组内按任务目录名排序。已完成任务仍有未关闭项时明确标注，不能折叠或省略。

### 遗留问题明细

| 来源任务 | finding ID | 问题摘要／位置 | 阻塞性 | 裁决及修复／复审状态 | 负责人 | 原始问题与后续处置链接 |
|---|---|---|---|---|---|---|

列出明确未关闭、延后及待核实的问题，包括非阻塞文档问题，不额外筛除已完成任务。负责人缺失写「待指派」，其他缺项写「未知」。只知计数而无法定位明细时保留总览计数，在此注明对应任务的明细缺口，不能输出「无遗留问题」。已关闭条目仅在解释冲突时引用。

### 状态异常与覆盖缺口

按任务列出缺失文件、契约异常、状态或计数冲突、裁决不明与读取失败，并链接证据。没有异常或遗留项时各用一句说明；只有覆盖完整且来源可核实才声明「无遗留问题」。

输出后停止。不生成五节阶段交付、不更新项目或任务索引、不提议 verify。报告链接仅用于溯源，不改变原任务的有效决定与完成状态。
