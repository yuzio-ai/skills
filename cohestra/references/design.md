# design

通过 $cohestra design 调用；与 [公共流程](workflow.md) 一起执行。

## 调用

```text
$cohestra design
.yuzio/cohestra/handoffs/<task-slug>/need-01.md
```

从中间阶段起步（样式探索、方案调整）时，直接给需求与参考：

```text
$cohestra design
需求：<要探索的页面与目标>
参考：<截图、现状链接或设计规范>
```

## 输入与职责

输入为任务目录或 need 交付，读取已确认的需求、验收条件及必要规范。业务实现只读，允许写设计交付、任务索引和任务所需的设计产物；正式文档按公共流程第 5 节处理。需求尚未确认时可调查并列方案，不能把建议写成已接受决定。

## 本阶段工作

1. 结合代码、规范和 AC，给出推荐方案、取舍、影响模块与状态边界；同类组件和视觉探索范围按[公共流程第 3 节](workflow.md#3-决策与执行强度)确定。
2. 写明实施步骤、依赖、文件所有权及完成条件，让执行者无需重新作重大产品或架构决定。
3. 将 AC 对应到证据类型、方法、环境、授权及缺失前提；记录所选方案与确认来源，建议与待决定事项不写成已接受决定。
4. 按 [风险覆盖](review-coverage.md) 识别需追踪的调用方、装配与生命周期路径，确定设计/验证深度、执行者数量及审查安排，按公共流程第 3 节说明依据、整改复查责任和触发条件。
5. 交付方案、执行计划、范围与状态清单、AC 证据映射、审查安排、可选项及停止条件。既有设计仅修订受影响部分，保留有效决定来源。
