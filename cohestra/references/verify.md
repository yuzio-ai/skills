# verify

通过 $cohestra verify 调用；与 [公共流程](workflow.md) 一起执行。verify 是横向的偏差核对，不是第七阶段，也不占阶段轮次；其编号独立于六阶段序列，规则见第 5 节。

## 调用

```text
$cohestra verify
被核对：.cohestra/handoffs/<task-slug>/design-01.md
上游依据：.cohestra/handoffs/<task-slug>/need-01.md
```

从中间阶段起步、任务目录里没有上游交付时，把上游依据写成本次实际提供的材料：

```text
$cohestra verify
被核对：.cohestra/handoffs/<task-slug>/code-01.md
上游依据：本次请求（<一句话复述>）与用户确认
```

不指定时按本任务目录中最近一轮实际交付与其直接上游核对，并在交付物中写明所选对象；存在多个并列候选时报告并请用户指定。

## 输入与职责

输入为被核对阶段的本轮交付物及其上游依据。只读被核对文件，允许写偏差核对交付与任务索引；不修复、不改写被核对交付、不补验收证据、不替代独立审查。

## 本阶段工作

1. 确定被核对阶段、轮次与上游依据的准确文件；任一项无法确定时报告缺口并停止，不用本阶段产出倒推上游。
2. 建立「上游条款/决定 → 本阶段产出」的对应表，覆盖目标、范围、AC、已确认决定、授权与停止线、明确保留项；上游没有对应条款的产出同样列出。
3. 按下列类型归类偏差，逐条给出位置与依据：
   - **遗漏**：上游要求或 AC 在本阶段无对应内容。
   - **越界**：本阶段新增了上游未授权或未确认的内容。
   - **偷换**：上游条款被改写、弱化，或 AC 被替换、重编号而不留来源。
   - **口径不一致**：同一事实在上下游交付中的数值、命名或范围不同。
   - **未决被当成已决**：上游标为待决定或待确认的事项在本阶段被当作已确认。
   - **追溯断链**：本阶段结论找不到上游依据，或引用的文件与章节不存在。
4. 逐条判定处置：接受偏差并说明依据、修订本阶段产出、回上游阶段补充，或转用户确认；标注是否阻塞后续阶段。
5. 给出结论：一致 / 有偏差待处理 / 无法核对。无法核对时列出缺失的上游依据与恢复条件，不用空泛结论填充。
6. 记录执行者与方式。同一执行者自核必须明示；verify 通过不等于独立审查完成，也不取消既定的 review、复审或验收要求。

本阶段结果写核对对象、偏差清单（类型、位置、上游依据、影响、处置）、结论与遗留项；一致时也要写明核对范围与未覆盖部分。

## 常见核对位置

| 被核对阶段 | 上游依据 | 主要风险 |
|---|---|---|
| need | 原始请求与用户确认 | 需求被放大或缩水，AC 不可验证 |
| design | need 交付 | 方案未覆盖某条 AC，引入未确认决定 |
| code | design 交付 | 实现偏离选定方案，漏改同类组件，越界改动 |
| fix | review findings 与整改授权 | 未命中 finding，顺手扩大范围 |
| review | design 约定的审查安排与被审候选 | 审查范围与依据不符，把作者自审当独立审查 |
| validate | need 的 AC 与验收结论 | 未验证项被写成通过，证据与 AC 不对应 |

## 交付与停止

新增 `verify-<轮次>.md`，编号独立于六阶段序列；骨架字段、落盘顺序、索引同步与停止规则见 [公共流程](workflow.md)。「输入与上游依据」写明被核对阶段与上游文件，任务索引按 `verify-<轮次>` 登记该行。

对口 verify：不适用——verify 本身不是被核对的阶段，交付后不再次提议。按原计划推荐下一阶段；有偏差待处理时推荐回上游阶段或补一轮修订，不自行改写被核对交付。
