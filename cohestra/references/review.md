# review

通过 $cohestra review 调用；与 [公共流程](workflow.md) 一起执行。

## 调用

```text
$cohestra review
.yuzio/cohestra/handoffs/<task-slug>/code-01.md
```

## 输入与职责

输入为任务目录或 code/fix 交付，读取有效需求/设计、固定候选、前次 findings 及复审要求。业务文件只读，允许在授权范围内做审查检查、写审查交付与任务索引，不自行修复。

## 本阶段工作

1. 从 code/fix 来源核对固定候选，按[公共流程第 4 节](workflow.md#4-候选证据与完成)确认可复核性；候选无法固定时不形成正式结论。
2. 从源码与实际路径独立核查需求、设计、正确性、异常路径、状态交互及必要测试，允许质疑设计。作者摘要与 PASS 不构成独立证明；执行必要的针对性检查，已有证据先核对来源、候选和适用范围。
3. 首次覆盖相关范围；复审按公共流程第 3 节先核对候选差异，再检查原 findings 和受影响断言，有新依据才扩大范围。
4. 每项 finding 记录稳定 ID、类型、严重度、阻塞性、位置、触发条件、后果、依据和验证方法；按公共流程区分确定缺陷、待核实问题与可选建议，标明原有问题或新回归。
5. 记录实际审查者、方式、覆盖范围和证据限制，列出剩余检查、复审状态及前提。无问题也说明范围和限制；项目要求独立报告时另存并链接。
6. 将未关闭 findings 计数（blocking / non_blocking，必要时 unresolved）写入交付物与任务 README Front Matter，字段和出口按公共流程第 7 节。

## 交付与停止

新增 `review-<轮次>.md`；骨架字段、落盘顺序、索引同步与停止规则见 [公共流程](workflow.md)。

必做整改转 fix，否则转 validate。列出剩余证据、可执行条件、缺失前提和负责人；全部受阻时只需最小核对与简短待验证交付。
