# code

通过 $cohestra code 调用；与 [公共流程](workflow.md) 一起执行。

## 调用

```text
$cohestra code
.yuzio/cohestra/handoffs/<task-slug>/design-01.md
```

从中间阶段起步（接口参数、页面样式的明确小改）时，直接给需求与范围：

```text
$cohestra code
需求：<改动内容与范围>
参考：<相关文件、接口文档或截图>
```

## 输入与职责

输入为任务目录或 design 交付，读取有效需求、已确认设计、验收条件和实施授权。允许在授权范围内实现、检查并写本阶段交付；关键方案未决或实施未授权时，先完成独立的只读核对并报告缺口。

## 本阶段工作

1. 核对工作区、输入版本和文件所有权，完成授权范围内的最小完整实现、相称测试与作者自审；同类组件修改核对实例和状态遗漏。
2. 按[公共流程第 3 节](workflow.md#3-决策与执行强度)处理局部修订、偏差及范围变化，记录确认来源和 AC 影响。
3. 按公共流程第 4 节执行相关检查、固定候选，保存基线、任务文件与精确差异；检查证据绑定候选，区分本次回归、原有失败和环境限制。
4. 交付实际修改、偏差、候选清单、作者检查、证据限制及审查重点。后续轮次只写变化，未变上下文按第 5 节引用。

评审输入同时提供已知的调用方、装配与生命周期入口；固定候选按 [风险覆盖](review-coverage.md) 包含必要未修改依赖或其可复核版本。列表是审查线索，不是作者代替 reviewer 出具覆盖结论。

## 交付与停止

新增 `code-<轮次>.md`；骨架字段、落盘顺序、索引同步与停止规则见 [公共流程](workflow.md)。

推荐下一步 review，传递本轮 code 与固定候选；缺少可审条件时准确说明。Cadra 派发时将独立 reviewer 所需的有效决定、候选清单和证据来源写入交付，随后停止，由编排者派发 review，不自行审查后宣布独立评审通过。
