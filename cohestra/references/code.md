# code

通过 $cohestra code 调用；与 [公共流程](workflow.md) 一起执行。

## 调用

```text
$cohestra code
.cohestra/handoffs/<task-slug>/design-01.md
```

从中间阶段起步（接口参数、页面样式的明确小改）时，直接给需求与范围：

```text
$cohestra code
需求：<改动内容与范围>
参考：<相关文件、接口文档或截图>
```

## 输入与职责

输入为任务目录或 design 交付，读取有效需求、已确认设计、验收条件和实施授权。允许在授权范围内实现、检查并写本阶段交付；关键方案未决或实施未授权时，先完成独立的只读核对并报告缺口。

## 本阶段工作

1. 核对工作区和输入版本，明确文件所有权；其他任务改动不纳入候选、不覆盖。
2. 完成最小完整实现、相称测试和作者自审；局部实现细节自主处理，同类组件修改核对遗漏的实例与状态。
3. 用户明确的局部修订记录来源、覆盖条款及 AC 影响。重大取舍或范围变化回到 need/design，共享语义先走项目治理；继续不受影响的已授权部分。
4. 执行相关检查，区分源码、编译和运行证据；记录本次回归、原有失败或环境限制。环境受阻时编译正确性仍未知，不降低门禁。
5. 固定可复核候选，优先引用 commit；允许未提交候选时在本轮交付物中列出基线、任务文件（含未跟踪文件）、精确差异与必要摘要，不为生成候选自行提交。
6. 写实际修改、偏差、新证据与未决项；后续轮次引用前版未变内容。交接文档与业务候选分开，不对文档自身做递归摘要。

本阶段结果写实际修改、偏差与确认来源、固定候选、作者检查、证据限制及审查重点；命令、环境和结果绑定候选。

## 交付与停止

新增 `code-<轮次>.md`；骨架字段、落盘顺序、索引同步与停止规则见 [公共流程](workflow.md)。

对口 verify：建议核对 code 与 design 的偏差。正式代码验证关口仍是 `$cohestra review`，两者不互相替代。

推荐下一步 review，传递本轮 code 与固定候选；缺少可审条件时准确说明。
