# 索引发布与恢复

正式阶段与 verify 准备更新任务索引时读取本文件；init、report 不读取。文件命名、交付不可变与写入所有权见[公共流程第 5 节](workflow.md#5-落盘与共享写入)，契约及状态映射见公共流程第 7 节。发布只维护任务 README，不授权提交或发布业务产物。

## 发布顺序与校验

落盘顺序固定：① 阶段执行完成 → ② 写本阶段 handoff → ③ 回读 handoff → ④ 基于重读的 README 一次准备 Front Matter（[公共流程第 7 节](workflow.md#7-机器可读契约orchestrator-contract)）与正文索引的完整新内容 → ⑤ 在独立工具调用中校验完整待发布内容的 YAML、阶段/轮次、候选、正文推荐与 `next`，本轮为 validate 时还须按公共流程第 7.3 节联合校验完成状态；收到并确认校验成功结果后，再用后续工具调用把同一完整内容写入 README 同目录的唯一临时文件并回读 → ⑥ 再次核对原 README 未变，用同文件系统的原子替换发布完整 README，再回读核对完整内容及同一组完成状态 → ⑦ 停止。校验不通过时不得发布或报告索引同步成功；仅为本轮结果漏写控制字段时，在待发布内容中补齐后重新校验，不通过降低验收结论消除字段冲突。首次创建时同样核对目标仍不存在。不得分两次发布 Front Matter 与正文；临时文件仅用于发布，不是第二状态源，成功或放弃后清理本执行者的临时文件。同任务并行时指定唯一索引维护者；重读比较不替代文件锁或写入所有权。发现并发更新、所有权不明、冲突或工具不能安全原子替换时保留阶段文件并报告“索引待同步”，不覆盖未知更新。`verify` 沿用完整文件发布流程，但仅改变正文，保留已有 Front Matter 原值，无 Front Matter 时不添加。
   **发布前校验关口**：校验与依赖它的写入/发布必须串行，不能并行，也不能在尚未检查校验结果的同一次工具调用中继续发布。逐项检查校验进程退出码、解析结果与语义断言；缺依赖、非零退出、输出为空或不能确认成功都视为校验未通过，立即停止依赖它的写入/发布。后续日志命令成功或工具调用整体返回成功，不能抵消前置校验失败。已有适用解析工具可用时，可另一次调用补做完整校验，收到成功结果后才恢复发布；仅在事后补验通过不能追认先前发布成功。把成功校验绑定到待发布内容的路径、字节摘要、本轮阶段/轮次和候选；内容变更后旧校验失效，须重新校验。无法完成校验时保留 handoff，按下节失败处理报告索引同步失败，不绕过关口。

## 失败处理

交付物写入失败报告“交接未完成”及错误、待写内容；部分写入和索引失败单独说明，不宣称事务回滚或全部成功。handoff 已落盘而 README 校验、写入、并发检查、发布或回读核对失败时，必须逐字报告 `handoff completed`、`index sync failed` 两句，附错误、待写内容与恢复条件。失败后重新读取实际 README：与更新前一致则报告“旧版（首次创建时为未创建）”，与完整新内容一致则报告“新版”，读取失败、存在他人版本或无法判定则报告“无法确认”；不固定断言状态停留在上一轮。即使已是新版，本次同步失败信号仍要求消费方停止推进，待恢复时核对完整交付、阶段与轮次后再继续；不得只凭可读取的 `next` 宣称交接成功。
   本轮 validate handoff 已落盘且记录验收通过，但因校验、写入、并发冲突、发布或回读核对失败而未完成索引同步时，还必须逐字报告「验收通过，完成状态待同步」。该说明不新增任务状态枚举，不把验收降为 pending 或 failed；同时如实报告 README 的实际版本与任务状态，不能宣称完成状态已成功同步。即使失败后读到新版 completed，也须保留上述同步失败报告，恢复核实前不推进。

## 恢复

核对实际 README、本轮 handoff、阶段/轮次、候选与执行模式，仅在本轮结果可核实时按上述校验与发布流程同步完整索引。不重跑已完成阶段、不重置轮次；证据不足时保留记录并报告恢复条件。已有控制字段异常的边界见公共流程第 7.5 节。
