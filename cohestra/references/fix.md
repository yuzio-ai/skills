# fix

通过 $cohestra fix 调用；与 [公共流程](workflow.md) 一起执行。

## 调用

```text
$cohestra fix
.yuzio/cohestra/handoffs/<task-slug>/review-01.md
```

从中间阶段起步（已定位的缺陷）时，直接给症状、预期与范围：

```text
$cohestra fix
问题：<症状、预期行为、范围和参考>
```

## 输入与职责

输入为任务目录或 review 交付，读取原 findings、被审候选、有效需求/设计和整改授权。允许在授权范围内修复并写整改交付；不把可选建议自动转为本次实施。

## 本阶段工作

1. 对原 findings 逐条裁决接受、不接受并给依据、待确认或延后，区分认可判断与本次实施；可选项、范围变化和局部修订按[公共流程第 3 节](workflow.md#3-决策与执行强度)处理。
2. 针对性修复和验证，保留 finding ID；重复失败时按公共流程第 3、4 节复查根因、产物与测试假设。
3. 按[业务交付前的风险检查](review-coverage.md#业务交付前的风险检查)覆盖同一问题链路的相邻终态及受影响替代路径。按公共流程第 4 节固定新候选，记录相对被审候选的精确差异、任务文件和证据；复用仍适用记录，只重查受影响部分。
4. 交付 finding ID → 裁决 → 实施或延后理由 → 修改位置 → 验证证据 → 修复/复审状态，列出剩余问题、复审范围、责任和前提。已修复不等于审查通过。
5. 按裁决与修复结果维护任务 README Front Matter 的 findings 未关闭计数，语义和出口见公共流程第 7 节。

## 交付与停止

新增 `fix-<轮次>.md`；骨架字段、落盘顺序、索引同步与停止规则见 [公共流程](workflow.md)。

按既定要求转 review 复审，否则转 validate。Cadra 派发的 fix 必须转独立 review，包括从已定位问题直接起步的首次 fix；复审输入或角色条件缺失时按既有受阻路径交付，不跳到 validate。传递本轮 fix、原 findings、剩余证据与前提；未确定角色标待指派。

[closeout](closeout.md) 编排同样要求每次 fix 后转独立 review；执行者发布本阶段后停止，由其主会话核对并安排复审。

整改同步适用的文档、配置与测试，并按 [文档与清理要求](review-coverage.md#文档同步与替代内容清理) 处理替代内容。保留 finding ID，交付新候选与复审输入，收尾整改只更新当前收尾任务的契约，不改被审原任务或历史 Run 的当时结论。
