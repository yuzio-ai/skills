# validate

通过 $cohestra validate 调用；与 [公共流程](workflow.md) 一起执行。

## 调用

```text
$cohestra validate
.yuzio/cohestra/handoffs/<task-slug>/review-01.md
```

已有有效候选、只缺证据时，直接给任务目录或 code/fix 交付：

```text
$cohestra validate
.yuzio/cohestra/handoffs/<task-slug>/code-01.md
```

## 输入与职责

输入为任务目录、最终候选的 review，或按既定要求无需复审的 code/fix。读取有效验收条件、候选来源和适用证据。业务候选只读，允许在已有授权内补验证、写验收交付和任务索引，不自行修复或改写验收要求。

Cadra 派发时，独立 review 属于既定验收前提：核对审查者身份与本任务作者分离、被审候选与最终候选一致或存在可核实的适用关系、fix 后所需复审已完成。角色名称、作者 PASS 或其他候选的旧 review 均不能代替这些证据。缺必要复审且条件齐备时交付 pending 并推荐 review；身份、输入或执行条件缺失则 blocked。worker 不得自行补作独立 review 或修改业务候选。

## 本阶段工作

1. 按 [风险覆盖](review-coverage.md) 核对覆盖证据是否对应最终候选；已有 review 漏掉必要路径时按现有 pending → review 或 blocked 出口处理，不重复静态审查或自行降低要求。核对最终候选、有效 AC、必做 findings 及必要复审，从 code/fix 引用候选清单；按[公共流程第 4 节](workflow.md#4-候选证据与完成)判断证据适用性和缺口，不重复静态审查填满阶段。
2. 对已有授权和执行条件的缺口按 AC 补证据，记录 AC → 证据来源/本轮新增证据 → 通过/未通过/未验证；复用项只引用。新增检查全部受阻时，最小核对后简短记录缺口和恢复条件；已有证据齐全时可据此验收。
3. 将整体验收判断写入交付物及 Front Matter.acceptance.status，条件与出口严格按公共流程第 7.3 节：确认失败优先转整改；缺必要复审且可执行时推荐 review；仅本阶段可补且条件齐备的证据缺口才允许再次 validate；缺输入、权限或执行条件时受阻。不自行复审、修复或降低验收要求。
4. 分别判断验收、实现、审查和提交状态，按公共流程第 5 节记录适用结果及缺口。只有范围完成、必做问题关闭、所需复审完成且必要证据齐全时才判 passed，并联合写入第 7.3 节规定的完成字段。

## 交付与停止

新增 `validate-<轮次>.md`；骨架字段、落盘顺序、索引同步与停止规则见 [公共流程](workflow.md)。

按验收结论交付完成结果或推荐相应阶段，说明缺口、前提与负责人。最终回复分别说明验收结论与索引同步结果；同步失败按[索引发布与恢复](publication.md)报告，不降低已成立的验收结论。
