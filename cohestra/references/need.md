# need

通过 $cohestra need 调用；与 [公共流程](workflow.md) 一起执行。

## 输入与职责

输入为原始需求及参考材料，或已有任务目录/handoff。首次任务先核对没有同目标任务，才建立任务目录；需求修订复用原目录。业务文件只读，允许写需求交付与任务索引。

## 本阶段工作

1. 通过必要的只读调查明确原始症状、目标行为、范围与排除项；区分已验证事实与假设。
2. 形成稳定 AC ID 及对应证据要求，明确哪些观察才能证明问题解决；已有 ID 保持含义，新增条件使用新 ID。
3. 记录范围、复杂度、风险与关键未知项；事实不清先调查，只询问实质影响目标、范围或验收的问题。
4. 记录必要参考、指定技能及产物要求。视觉任务明确文字方案、探索图或实现预览，并核对截图外受影响的同类组件与状态。
5. 提前列出验收证据、环境、授权与缺失前提；缺少运行授权不妨碍独立的只读调查。
6. 判断是否具备 design 条件。需求修订只写变化、确认来源和受影响的设计/AC，继续引用未变内容。

本阶段结果写目标、范围、AC、参考与产物、事实/未知项、初步分档及 design 前提。新索引只登记实际发生内容。

## 交付与停止

在原任务目录新增 `need-<轮次>.md`，采用 [交付骨架](../assets/handoff.md)，按公共流程落盘、回读并串行同步任务索引。

通常推荐 design，传递本轮 need、关键未决项和负责人。下一步使用 `$cohestra <阶段>` 加本轮交付物或任务目录与补充指令；交付后停止，不自动执行下一阶段。
