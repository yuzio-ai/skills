# 本机账本与正式报告

`.yuzio/` 是当前工作区的本机执行资料。默认 `.yuzio/relatra/` 保存配置、采集快照、完整账本和可复算报告；这些资料可能包含本机来源路径和私人工作记录，不自动进入项目文档或 Git。忽略不代表可随意删除：复算所需 facts、manifest 和各版账本仍须保留。

执行者在首次写入及复用前检查目标 Git 工作区根 `.gitignore`，最小追加 `/.yuzio/`（已有效覆盖不重复），保留其他规则并核对实际生效。已有跟踪文件只报告，不自动移出索引、暂存或提交。项目显式跟踪要求、反向规则、并发或权限冲突待处理，忽略未生效前不继续写本机资料。仅讨论或只读查看不修改规则；Git 仓库外的报告目录不创建 Git 配置。脚本只负责报告数据，不自动管理 Git；上述检查由调用技能的执行者负责。

## 正式报告

根据任务目标、报告用途和适用项目规范判断是否需要项目正式报告，需要时在已有任务范围内自动整理，不等待用户另行要求“归档”或“保存到 docs”。例如任务用于团队周报、项目交付汇报，或项目规范要求保存周期报告时，优先更新项目文档目录中的相应报告，无约定时用 `docs/reports/`，补齐必要证据摘要与稳定引用。

个人复盘默认保留本机结果，不因生成了报告就自动转成项目文档。只讨论、纯只读和明确不落盘的请求保持原限制。目录可从已有上下文或约定确定时不重复询问；仅在报告受众、跨项目范围等影响正确性或共享边界的关键信息无法确定时澄清。跨项目报告沿用本任务已经确定的共享目的地，不能自动放入某个项目泄露其他项目内容。

正式交付同时保存重点正文和配套可读明细，保留周期、范围、统计结论、具体成果、限制、待办及必要证据摘要。按项目约定命名正文及其配套明细，改名时更新相对链接并保留任务锚点；不能只交付正文使明细入口失效。引用项目正式文档或可持久访问的明确来源，不能只链接 `.yuzio`、本机绝对路径或原始会话日志。正文和明细均移除不必要的个人信息和本机路径，保留证据不足的限制；不复制原始 facts、日志、全部账本或更正历史。正式报告与明细路径、来源版本记录在本机资料中。归档不改原快照与哈希、不改变验收结果、不自动提交或发送。
