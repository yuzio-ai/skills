# 最终整体确认独立真实会话实测

日期：2026-11-06（Asia/Shanghai）。实际执行未提交的 Cohestra 0.17.0 / 协议 0.8，使用六个隔离 Git 项目和六个无父会话历史的原生 agent 会话；另有一个独立只读裁决会话。全部执行者使用同一冻结技能包，逐文件摘要与当前仓库一致。

## 结果

| 场景 | 实际行为与控制结果 |
|---|---|
| need 单项已答、仅授权代选 | 给出完整汇总，要求整体认可；索引为 blocked / human_decision_required，next=null/false |
| need 拒绝整体确认，再认可 | 拒答后仍 blocked；认可后新增 need-03，stage completed、任务 in_progress、next=design/true；need-01/02 摘要不变，没有执行 design |
| design 修订后重确认 | 首轮完整 JSON 方案待确认；改为逐条 Markdown 后重发完整方案，仍不交付完成索引；明确整体认可后才完成 design，没有执行 code |
| need 明确免除最终确认 | 保留完整汇总，记录免除来源，完成当前阶段；next=design/true，不追加确认或执行后续阶段 |
| design 无人值守、普通代决 | 未将“无需逐项请示”当作免除整体确认；直接 blocked / human_decision_required，next=null/false，没有等待交互 |
| need 复用已认可原文 | 引用同一完整需求及确认来源，没有新增取舍、重复确认或执行 design；next=design/true |
| design 仅免除整体确认，拒绝格式代决 | JSON/Markdown 保持未定，未设置默认；仍 blocked / human_decision_required，不因免除整体确认获得取舍授权 |

表中 need 的前两行来自同一多轮会话；总计六个执行会话、十个执行回合。最终六个场景均通过只读核对。原始业务输入及夹具 HEAD 不变，没有生成 code/review/fix/validate 交付。完成状态不构成实施授权，实际均在当前阶段停止。

## 核对器误报与独立裁决

design 修订场景认可后的任务索引使用了 `status=completed`、`next={null,false,task_completed}`。原核对器只接受 `in_progress` 与 `next=code/true`，因此报出两项错误。

独立裁决会话读取原始请求、完整问答和冻结规则后认为：用户明确“只完成 design”，并将 code 留待单独调用，可以适用既有“用户声明终点”分支；交付也明确没有实现、审查或验收结果。没有足够依据把这个合法组合认定为技能缺陷。

据此修正核对器，仅为该已裁决场景允许完整的合法终态组合；等待确认和受阻场景仍严格禁止 completed 或允许后续动作。原始误报检查点持续保留，裁决前后的实际索引与所有产物摘要完全一致。没有改写 agent 产物来消除误报，也没有为此追加技能规则。未据本场景宣称该终态可直接接入 Cadra 后续执行。
