# Relatra 0.2.0 精简验证

日期：2026-10-22，Asia/Shanghai。范围：Relatra 技能、脚本、双语入口及离线回归。数据结构 schema v2；未安装、提交或发布，不执行源业务任务。

## 已实现

- 账本复用：按范围及截止选择前版，校验哈希与引用；只把本期未归属活动、变化证据和未闭合目标列为待审阅。失配目标保留身份、清除无效判断并显示待核实。历史保留用于首次交付与跨期核对，初始覆盖限制不会因复用而消失。
- 正文精简：普通模式集中展示成果、遗留、主要资源与覆盖；无基线或建议时无空章节。事件、证据、逐字段资源和诊断仍在 JSON。
- 按需分析：basic 默认；deep 需复核本期过程证据并明确 process_reviewed。复用重置完成声明，未统计为 null。不同模式可比较满足覆盖条件的核心指标；过程比较要求双方完成深度分析且满足覆盖条件。
- 完整账本更正：移除 correct/--correction；以 --tasks、--revises、--reason 生成新版本。修改已生成报告的账本不能省略更正元数据；原报告及源日志不变。

## 复查结论

四项优化均核对了实现、使用说明和回归覆盖。复查先用合成输入复现以下三处遗漏，再修复并添加针对性回归：

| 问题 | 修复与验证 |
|---|---|
| 已完成目标保留自动候选 ID 时，同聊天新轮次可能被直接合入旧目标 | 候选 ID 包含本批未归属轮次；移除按旧 ID 隐式合并分支。新目标继续待判断，原目标轮次不变 |
| 未直接作为交付证据的子任务日志删除，父目标没有进入复核队列 | 比较新旧后代集合，移除也触发复核；已知轮次消失另记覆盖缺口，有效的父目标交付证据不被清空 |
| 固定历史覆盖提示使双方始终“都有警告”，新增读取错误未阻止效率比较 | 固定范围提示与采集诊断分开；任一方有实际诊断时仅并列观察值，不据此判断改善 |

前版选择改为只保留当前最佳候选，避免同时持有全部历史报告的完整 facts/ledger；未引入数据库、缓存索引或迁移层。普通/深度两个模式、复核标记和更正元数据各有明确用途，本轮未发现值得新增或继续拆分的机制。

Python 3.14.8 与 3.9.6 的 89 项回归均通过，包含隔离副本的完整 CLI 链路；原生技能校验及改动空白检查通过。此结论限于源码审查、合成场景和现有回归，不替代真实历史规模下的使用验收。

## 限制与兼容

旧格式保持可读，不自动迁移或支持复算；继续处理需重新配置和采集。深度分析的语义真实性仍依赖 agent 核读证据，脚本不会以布尔声明替代内容判断。未开展新的真实历史使用验收、独立 agent 使用验收或安装测试。
