# Cohestra validate 实际调用验证

2026-10-15，Asia/Shanghai。Cohestra 0.10.0，协议 v0.8。

## 结论与未通过项

**未全通过：最终 39/40 个用例通过，1 个未通过。未更新已安装副本。**

未通过项为 run2 / case-03（无 Front Matter 的旧任务）：执行者的发布前 YAML 校验因缺少 PyYAML 返回非零，但仍继续调用发布驱动，README 被实际替换。之后 Ruby Psych 解析和完成字段核对通过，执行者在实际回复中保留了 `handoff completed`、`index sync failed` 和「验收通过，完成状态待同步」。最终 README 为 completed 不消除先校验再发布的顺序违规，本例不能计为通过。

当前公共流程第 5 节已经禁止校验不通过时发布。本次观察证明文字规则在这次执行中未被遵守，不能据此声称执行过程已有程序级强制保障。需要修正实际执行的控制顺序：检查校验结果后才允许调用发布，校验未通过时先停止或换可用工具完成校验，再重新验证此分支。

首轮另有 case-03～08 的 handoff 使用了估算分钟，晚于文件实际创建时间。原始交付未改写；在全新目录复跑这 6 例。复跑 case-04～08 通过，case-03 出现上述发布顺序问题。原始问题、复跑和未通过结果均保留，未用复跑覆盖失败证据。

## 实际执行与证据

- 将新增 11 组场景展开为 40 个隔离项目；首轮 40 次阶段调用，另复跑 6 次，共 46 次（44 次 validate、1 次 review、1 次 verify）。
- 首轮由 3 个新上下文子智能体分别执行 case-01～14、15～27、28～40；复跑由第 4 个新上下文子智能体执行。执行者只收到技能路径、原始项目、实际请求和测试环境文件操作约束，没有收到作者预期答案或场景判定表。
- 业务夹具为固定摘要的加法候选、有效需求和检查脚本。执行者实际判断验收、编写五节交付和 README、保存最终回复与真实检查输出。
- [夹具与发布驱动](cohestra-validate-fixture.py) 只建立输入、执行临时文件写入/原子替换/回读并注入故障，不做验收判断，不生成执行者的交付或回复。[只读核对器](cohestra-validate-check.py) 在执行后解析实际产物、核对候选、状态组合、错误报告和时间记录，不写业务产物。
- [完整证据](cohestra-validate-evidence.json) 保存两轮原始输入/实际交付/实际回复、真实检查结果、每次发布前后内容及错误、20 个技能文件的内容与摘要、逐例断言、时间审计和安装副本前后摘要。证据不以临时目录为唯一来源。
- 首轮结果为 34 通过、6 个时间记录失败；复跑结果为 5 通过、1 个发布顺序失败。按每个逻辑用例的最后一次执行汇总为 39 通过、1 失败；不是 46 次全部通过。

## 复现

在仓库根目录创建新的隔离套件，不覆盖已有目录：

```sh
python3 -B tests/cohestra-validate-fixture.py prepare /private/tmp/cohestra-validate-new-run
```

让独立执行者读取隔离套件中的 `skill/SKILL.md` 和各项目 `REQUEST.md`，实际完成指定阶段。每例的 README 只通过 `publish <项目目录> <完整草稿路径> <原 README SHA256 或 absent>` 发布；其他阶段交付正常写入。保存真实最终回复为各项目 `reply.md`，检查 stdout/stderr 与退出码为 `check-result.json`。原始 `controller.json` 和本报告的预期结果不提供给执行者。多个用例可以由同一执行者串行处理，本次不是 46 个独立会话。

执行后只读核对：

```sh
python3 -B tests/cohestra-validate-check.py /private/tmp/cohestra-validate-new-run
```

核对器返回非零表示有失败或未运行项。它不是 Cohestra 执行器，不能代替前面的实际技能调用。环境故障使用 POSIX 权限和受控并发改写，不能在正式业务目录执行。

## 边界

本结果是简单固定候选和受控文件操作上的实际技能行为证据，不证明任意业务项目、任意工具或所有并发时序都可靠。没有更改 Cohestra 源规则或真实业务任务；20 个测试技能文件与当前仓库源一致。已安装副本的前后逐文件摘要一致，没有执行安装更新、提交、推送或发布。CLI 帮助读取和安装前备份不等于技能已更新。
