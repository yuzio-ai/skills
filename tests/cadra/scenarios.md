# Cadra 验证场景

当前包和协议以 release.json 为准。原 v0.6 模型覆盖未变的流程/预算语义；新增 test_run_guard.py 直接运行包内 0.7 写入器，测试真实临时文件、进程竞争和旧记录只读边界。写入器依赖 Python 标准库和 POSIX 文件锁，不依赖仓库测试；离线验证不代替实际智能体调用。

## 结构与接口

- 六入口可发现，按需加载；状态解析、Gate、契约、预算和恢复只有一处权威定义。
- Task 保存 revision、preparation、定义及 Gate，Run 保存有序任务数组、previous_run、定义快照、调用与结果；没有独立队列文件或 Task 执行状态副本。
- flow 首项加允许集合，preset 与等价列表一致；未知阶段与空值拒绝，后续重复去重，不限制中间链序。
- Markdown 链接、元数据、模板字段、版本与契约匹配；双语说明内容对应，不锁定措辞或排版数量。
- .yuzio 本机存储、忽略规则、正式总结范围保留；0.6 只读识别，未完成旧 Run 不接管；Task 仅明确 add 升级，旧 Run 不双写、不覆盖。

## 行为场景

| 场景 | 预期 |
|---|---|
| add/ready | 只写定义与准入；八项 Gate；未完成 Run 所属任务不编辑 |
| 普通串行执行 | Run 固定顺序；只写 Run 执行状态；默认失败继续，策略停止时未执行项 skipped |
| 来源链 | 显式 previous_run；分叉、缺失、循环、重复 slug、修订倒退停止；不以时间选来源 |
| 新定义与依赖 | 旧 completed 不放行新修订；开始与续跑前重核依赖 |
| Flow | 等价 preset/列表同结果；正常范围边界收尾，必做后续超范围 blocked；复审不按列表位置推进 |
| 相同结果 | 无额外提前停止，允许契约许可且预算内的重试或补证 |
| 三项预算 | 重试 2、整改 3、调用 16；第三轮 fix 后仍可复审；第 16 次刚完成时保留完成结果 |
| 契约核对 | 缺字段、错 task/模式/阶段、旧轮次、同步失败停止；跨阶段独立轮次合法 |
| 中断边界 | Run 建立后、调用意图后、Cohestra 交付后、结果已写但 Run 未收尾分别恢复 |
| 派发不明 | 旧契约不证明未调用；无确证停止，只有明确未发起才沿用原 call id |
| 重复 resume | 已结束项不重跑，预算不重复消费；只补收尾，不重开结束 Run |
| 定义连续编辑 | 未入 Run 的同修订累计变更；requirement/flow 曾变更从新 start 起步 |
| skipped 与修订 | 未调用不消费授权；重新核对原准入；跨 skipped 修订累计变化不丢失 |
| 首调用前受阻与修订 | blocked/failed 无调用且未消费时不截断累计变更；仍核对原因解除；后续仅改策略也保留未执行的 requirement/flow 重启 |
| 执行依据 | prepared 意图须核对而非跳过；合法无调用收尾可作为依据；缺少消费证据不推定未启动 |
| 普通调用与特殊授权 | 普通调用及普通核对收尾可保持 authorization_consumed=false；失败后策略修订仍能找到执行依据 |
| 首调用前 running 中断 | 无调用、零预算、未消费且可证未派发时重核 start_action；准入失败或派发不明不调用；已有 prepared 只核对原调用 |
| Flow 起点改变 | allowed 相同但 start 改变仍使 Gate 失效；只有 start 与 allowed 都相同才等价 |
| 非法控制枚举 | next.reason、blocked.reason、acceptance.status 非法时 failed；缺省/null 的可选 acceptance 合法；不闭合调用或推进 next |
| 显式恢复 | 新 Run 引用旧来源，原 Run 不变；解除证据、旧调用核对及一次授权必需 |
| 历史报告 | 新成功不覆盖旧失败；新修订不改旧定义和报告，缺材料 unknown |
| 原子保存失败 | 原目标不被半写文件替换，回读失败不推进；无跨系统事务承诺 |

## 验证入口

包检查与行为模型统一运行：`python3 -B -m unittest discover -s tests/cadra -t tests -p 'test_*.py' -v`。模型只验证协议解释；实际多任务执行、中断恢复及故障场景需另行调用技能验证。

## add 读取与校验验收

以下为实际 agent 的流程验收要求；包检查只验证资源可达性，不证明读取范围、耗时或 token 节省。

| 场景 | 预期 |
|---|---|
| 普通新建、无依赖、无既有交付 | 按基础路径读取指定公共章节、定义、配置及模板，不加载 Gate、执行契约、预算、恢复或历史迁移；保存 draft，Gate 未检查 |
| 缺少验收细节、输入或产品决定 | 写明缺口，不编造结论，不为补齐 Task 调研业务源码、跑构建/测试或生成阶段文档；必要身份或安全信息不明时停止 |
| 依赖不存在、自依赖、可达依赖环 | 使用拟保存定义核对可达图，拒绝错误修改；合法但未完成的依赖可记录，不为 add 查询其执行状态 |
| 仅 title/priority，或语义等价 flow 编辑 | 仍核对目标来源链与归属；不改变 Gate、revision 或执行结论，不加载重启准入来选择下一阶段；已有 Run 且本次未分代时给 list 查询，不机械推荐 ready 重开 completed/blocked/failed 或重新解释 skipped |
| 影响 Gate 的定义编辑及同修订连续编辑 | 按当前修订是否已进入 Run 决定是否分代；保留 revision_base，累计 changed_fields，改回 requirement/flow 不清除曾变更依据；旧快照不变 |
| 未完成 Run 中本项已经结束、多个未完成 Run | 前者仍禁止编辑；后者报告归属异常，不因减少读取而跳过检查 |
| 来源链缺失、分叉、成环、修订倒退、协议未知或闭合不明 | 停止相关写入，按需读取异常规则；不以时间、run-id 或缺少 Task 文件推定无历史 |
| Task 缺失但存在 Run，或仅有 Cohestra 交付 | 前者报告恢复缺口，不新建替代；后者只有按身份绑定确认后才可准备 Task |
| 已有交付主题对应且上下文已明确确认 | 复用确认，记录主题及来源；只读索引身份和目标摘要，不重复索要确认或通读所有 handoff |
| 主题不符、绑定未确认、身份字段缺失/错误、版本不支持或 handoff 存在而 README 缺失 | 停止绑定并报告准确缺口，不静默收养、不代写索引 |
| 身份确认但控制契约、候选或首动作材料不完整 | add 记录已知缺口，不宣称可执行；ready 起点项加载完整契约核对并拒绝缺口未解除的放行，run/append 仍复核 |
| 旧 0.6/0.7 与明确升级请求 | 仅发现旧协议时加载兼容路径；未授权保持只读，升级保留来源、备份、确认和重新 Gate 要求 |
| 检查后目标、归属、可达依赖变化或出现同名记录 | 写前重读并重检受影响部分；还核对新出现的同名交付，绑定路径重读索引身份和目标摘要，旧确认不再适用时停止绑定；不覆盖并发更新，不复用跨调用缓存，不覆盖同名新文件 |
| 保存失败或回读失败 | 保持共同写入的原子性与冲突边界，不声称保存成功；最终只报告路径、slug、准备状态、必要缺口及可行下一步 |

读取范围的静态对比见 [add 规则读取量核对](reports/2026-10-26-add-reading-scope.md)。它不是实际 agent 运行证据。

## 收尾自动报告验收

以下流程需实际 agent 验收；guard 单测只证明报告链接的受限写入，不证明自动触发、输出质量或 token 节省。

| 场景 | 预期 |
|---|---|
| 正常 completed，或包含 blocked/failed 的 completed | 收尾成功落盘回读后，为当前 run-id 自动生成一次报告；包含各结果数量、逐项必要交付及人工事项，不因存在失败项省略报告 |
| 用户停止或 stop_queue_on_failure 策略停止，所有项均已终态 | 闭合 stopped 后自动报告；保留真实结果、skipped 原因与验收边界，不将停止等同成功 |
| running、interrupted、含 queued/running 的 stopped，或收尾写入/回读失败 | 不自动生成报告；保留恢复信息，不冒称 Run 已闭合 |
| resume 仅补收尾，或继续阶段后收尾 | 仅补收尾不重复工程调用；本次闭合并回读后自动生成报告，使用原结果与预算 |
| 对已经闭合的 Run 重复 resume，含缺少报告的情况 | 保持只读，不生成文件、补登记或重开 Run；可展示已有报告链接，缺报告时给出指定 run-id 的手动 report 调用 |
| 收尾成功后、报告生成前中断 | 执行状态保持闭合；手动 report 补齐，不要求 resume 重开 Run |
| 自动报告前已有手动进行中报告 | 原报告不覆盖，按新轮次生成收尾报告；自动流程不重新选择其他 Run |
| 报告文件生成失败 | 不回滚 Run 或修改任务终态、预算；最终回复分别说明执行结果与报告缺口，并给出准确 report 调用 |
| 文件已生成、链接登记失败或摘要冲突 | 保留原文件和准确路径；重读最新 Run 后只补登记该路径，保留已有链接，已登记则不重复追加；持续冲突停止重试，不为登记重试另生成报告 |
| 简单任务、复杂任务与证据缺口 | 优先使用 Run 快照及调用记录，按需读取相关证据；报告随复杂度调整，不复制全部 handoff/日志，不重跑 Gate 或验收，最终回复只提炼一次 |
| 历史 0.6/0.7 report | 只读对话输出，不生成文件、登记链接、迁移或修改历史结果 |

## list 展示验收

以下是实际 agent 输出的人工验收场景，不由包结构检查或协议模型证明；未执行时不得宣称展示已实测通过。

| 场景 | 预期 |
|---|---|
| 八种展示状态混合、部分状态为空 | 有 running Run 时先显示队列，否则从总览开始；其余分组按 running/queued/blocked/failed/unknown/ready/draft/completed 顺序，空组省略；顶部队列任务不在后续分组重复；总览包含顶部及收起的完成项，去重计数与总数一致；blocked/failed/unknown 保留简短原因 |
| 同组创建时间先后、同一时刻与不同时间偏移 | 按实际时刻升序，同一时刻按 slug；显示项目时区，缺省 Asia/Shanghai；分钟显示相同时仍按原始精度排序，不按 priority 或修改时间重排 |
| 正文创建记录、历史缺记录、非法值、无时区与冲突记录 | 明确的原始创建记录可用；其余时间显示未知并排在本组末尾，未知之间按 slug；不推测、不回填，不因此将任务状态改为 unknown |
| 状态过滤、多 slug、明确单 slug 与无匹配项 | 只统计与展示范围内任务；默认 completed 只显示数量；多任务行仅含标题、slug、创建时间及必要异常原因，队列另标状态和原顺序号；明确单 slug 补充元数据；无匹配项不输出空组 |
| 展开已完成任务、筛选 completed 或指定已完成 slug | 只展开本次范围内完成明细，按创建时间排序；不自动展开历史 Run；默认查询仍只显示完成数量 |
| Task 展示顺序与运行中 Run 队列顺序不同 | 队列置顶，隐藏 completed 条目但保留其他条目的 Run.tasks 顺序和原序号，未开始项不能按创建时间重排；顶部 Run 不在底部重复；Run 摘要保留进度、当前项及动作、追加批次和活性，角色完整身份按需展示；来源链与旧结果不变 |
| interrupted、未闭合 stopped 与已闭合历史批次 | 默认 Run 一览包含 interrupted 和仍有 queued/running 项的 stopped；已闭合 stopped/completed 默认隐藏；记录异常仍显式报告，不能被历史收起规则隐藏 |
| 查询历史 Run 或指定 Run 标识 | 明确历史查询显示历史一览；指定批次或要求完整队列时显示完整原始顺序和旧结果，包括 completed 条目，不用当前 Task 结果改写历史；默认查询不列历史批次 |
| 活跃、已停止待核对与活性未知执行者 | 保留活性结论及原有下一入口建议边界，不因 pending_call、prepared 或久未更新推荐接管；list 前后 Task/Run 字节不变 |
| 当前调用 prepared/dispatched，分别处于 code/review/fix/validate | checkpoint 与调用、角色及派发证据匹配；prepared 显示待派发对应阶段，dispatched 显示实现中/评审中/整改中/验证中并标明交付待核对；阶段文案不作为工具活跃或交付通过的证据 |
| 当前调用已闭合或尚未登记，交付契约有/无明确下一步 | 只用最近已闭合调用中已核实且允许的 next 显示等待阶段；无明确合法下一步时显示待核对后续动作；不按 flow、旧阶段或聊天描述推测 |
| pending_call 指向不存在/已闭合调用、派发证据缺失或阶段冲突 | 当前动作显示未知及具体缺口，不沿用旧调用；只有状态来源本身矛盾才将任务状态改为 unknown；历史 need/design 仍按旧协议解释 |
| 默认查询、明确角色/Run 详情、指定 Run 或单个 slug | 默认不显示角色完整 ID 及宿主身份字段；详情仅展开范围内实际登记信息；身份冲突、活性未知仍用一句提示保留；下一步建议规则保持不变 |

## 执行预检与归属回放

- Run 03 的不完整示例：项目预检失败不建 Run；任务级问题排除该项，不改历史快照。Mewoo 的无关草稿不再进入全局门禁；真实命令仍拒绝错误参数。
- 执行者 active、notLoaded、idle 且工具未知、缺身份、陈旧观察或无宿主能力：查询不写记录，不能接管或单凭时间推断中断。
- 两个恢复进程对同一摘要和代次竞争：至多一个成功；另一个重新读取，不覆盖新 owner。
- 完整交付尚未登记：接续保留 call id 和预算，补结果不重派发。
- 宿主观察须逐项匹配 host/chat/turn；身份不全只保留未知。明确人工停止交接可承载未知字段，但普通 resume 授权不能替代停止证据。
- 接管不改 Run 正文；来源链、唯一 Run、定义快照先只读核验。新的 prepared 意图只能在原调用单独闭合落盘后追加，不能同次伪造已交付调用。
- 旧 0.6 running/stopped 未核实关闭：新版本禁止创建替代 Run，历史字节不变。
- 旧 0.6 completed/stopped：块 YAML 两种列表缩进和 JSON 均核对任务终态及匹配结果；重复字段、缺结果、重复 slug、嵌套定义干扰和未知协议不能误放行。
- Task 协议升级：先验证备份与 hash；没有明确升级请求或存在未完成 Run 时不写。迁移本身不修改 revision/requirement 或终态，随后 Gate 重核。此项为 agent 流程验收，不把 guard 测试冒充迁移实测。


## 0.8 队列与角色隔离

- 旧 code/fix 终点 completed、next=null 接续：普通准入、恢复核对及仅策略/依赖修订收尾均不得绕过后续独立评审。不含 validate 的显式 flow、review-only 或历史 acceptance=passed 仍应受阻；旧交付和预算不变。Cohestra 经明确授权补审/恢复索引后，重新按新契约准入；已有合法 review/validate 交付仍可按原要求沿用。
- 默认 implementation；bugfix/review-only 保持各自边界。新版拒绝已移除的预设及 need/design 列表；历史 0.6 模型继续单独验证旧语义。
- 返回 need/design 必须 blocked；显式缩小列表不能跳过 code/fix 的必要独立 review。
- append 整批通过或整批拒绝，只增加已准入任务后缀；重复请求、旧摘要、修改前缀、混入其他字段及陈旧预检均不得发布。
- 追加与追加、阶段落盘、收尾竞争时，已接受任务不得丢失，已结束 Run 不重开。
- 新任务干净上下文；同任务 worker/reviewer 角色分离且阶段串行；原绑定必须先落盘再准备调用。
- 新绑定、派发、完整交付分别核对；pending 不可改派；复用同一 agent 的后续活动会使旧停止证明过期。
- 父停止但子 active/unknown 时不接管；claimed_at 不早于所有停止证据；恢复不重算已消费预算。
- 临时项目另验连续两任务、运行中追加、真实整改复审及缺少子 agent 的受阻边界。记录真实执行、故障注入和未覆盖项，不能把模型结果当作宿主实测。
