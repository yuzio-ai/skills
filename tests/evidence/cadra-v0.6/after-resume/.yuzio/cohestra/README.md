## 使用

在智能体中使用 `$cohestra need`、`design`、`code`、`review`、`fix`、`validate` 或 `verify`，后附原始需求、已有 handoff 文件或任务目录及本次补充；六阶段可从任意阶段起步；未指定阶段时按任务目标自动选择一个起点，交付后停止。目标项目尚无本目录时，技能会先提醒并执行一次最小初始化，再继续该阶段。其他工具使用各自的技能调用写法。

使用 `$cohestra report` 只读查看本项目全部任务状态、遗留问题与状态异常，包括已完成任务的未关闭项；结果直接在对话中展示，不初始化项目、不写文件或推进阶段。

- [handoffs/](handoffs/)：每个任务一个目录，其 README 保存有效决定、候选、分开的状态和下一步；阶段结论单独落盘。
- [retrospectives/](retrospectives/)：按需保存复盘，不作为每阶段必读输入。
- 规则和阶段提示词保存在技能包中，不在此复制。业务规范仍归项目所有；历史决定、授权和验收证据按任务索引追溯。
- 普通任务只更新自己的交付物与任务索引，不反复更新本入口。每轮交付记录实际采用的技能发行版本，历史文件不随技能升级重写。
- 用户级技能升级影响后续调用；需要项目独立固定版本时，选择项目级安装并通过 Git 管理更新。

本目录属于工作区本机资料，根 `.gitignore` 用 `/.yuzio/` 整体忽略。任务记录仍须保留；正式文档与必要共享证据写入项目已有文档目录（无约定时用 `docs/`），不能仅引用本目录。任务 `scratch/` 用于可重建日志与产物。接续任务复用当前项目的索引与交付记录，Git 不备份本目录。
