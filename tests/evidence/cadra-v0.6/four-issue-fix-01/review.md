## 修复与回归

| 问题 | 修复 | 回归覆盖 |
|---|---|---|
| 普通调用授权标记 false 被误判异常 | 调用意图或有效无调用收尾独立构成执行依据；授权标记仅表示特殊恢复/修订授权消费 | 默认 prepare → 恢复失败 → 策略修订；普通/特殊授权两种无调用收尾；原连续未执行修订场景 |
| running 且首次意图未写入的恢复缺口 | 增加重核原 start_action 的分支；要求零预算、未消费、无调用/交付记录及明确未派发证据 | 落盘重读后的调用/收尾动作选择；准入不通过、派发不明、记录矛盾时不继续；已有调用沿用原 id 与预算 |
| Flow 排列豁免覆盖起点改变 | 仅 start 与 allowed 均不变才算等价；起点改变仍需 Gate 与修订 | allowed 相同但 start 改变；后续重排与重复项保持等价；新起点进入修订 |
| 非法控制枚举被放行 | 校验 next.reason、blocked.reason、可选 acceptance.status 的值与形状，保留 acceptance 缺省/null 合法性 | 非法字符串、容器、数字和布尔值拒绝；无效交付不闭合调用、不触发 next；allowed=false 要求 stage=null |
| 独立复核追加：candidate 形状和叶子类型 | 要求映射及 commit/snapshot 两叶为字符串或 null | 列表、数字、嵌套对象等不能完成或闭合；合法候选来源仍接受 |

## 验证边界

本轮为规则推演、测试模型和函数组合验证，未重新执行实际 Cohestra 工程阶段。resume_unstarted 只选择已核准的动作，不负责实际派发；不能把选择成功当成工程调用成功。模型也不是完整契约/发布验证器，findings 等报告字段的类型未建模；这些限制没有被计为“全字段验证通过”。

skill-creator 原生 quick_validate 在此前确认缺少 PyYAML；本轮未改 YAML 元数据/模板，未重装依赖，也不将静态检查等同原生校验通过。
