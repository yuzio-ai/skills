# Relatra 计划覆盖与验收

审查日期：2026-10-13，Asia/Shanghai。范围：Relatra 技能包、双语入口、离线测试及独立 agent 的真实日志使用验收。未提交、发布、安装技能或运行原业务任务。

## 计划覆盖

| 计划项 | 当前实现与验收依据 |
|---|---|
| 独立技能、Codex 优先、个人复盘、明确项目集合 | [SKILL.md](../relatra/SKILL.md)、[UI 元数据](../relatra/agents/openai.yaml)、configure；保留后续适配器接口及本地覆盖限制 |
| 日/周/月/季/年/自定义，中文、上海时区，默认上一完整周期 | period_window；自然周期、DST、闰年、自定义及阶段性测试 |
| 目标为任务，单聊天多目标、跨聊天归并、子 agent 合并 | 候选交由 agent 判断；稳定 id/revision、turn/root 引用、共享资源未知、嵌套子任务及多项目测试 |
| 交付与验收分开，成果具有目标/变化/证据/限制/下一步 | 事件 basis 与验证分类、源引用/去敏摘录；实现自述不算交付，实际咨询答案可交付；起点也需证据 |
| 流量、期末状态、重开、范围修订、失败历史 | 首次交付按修订计数；最新修订计目标存量；重开不新增同修订交付，旧版本和失败记录保留 |
| 完成周期、执行时长、并发占用、交互和等待 | 基础区间裁剪、并集、中位数附样本；交互按用户消息时间，历史 open turn 不推算执行活动 |
| 返工、重试、范围调整、验证、人工介入分类 | 稳定过程事件 id 去重及冲突拒绝；验证类别校验；未记录不解释为未发生 |
| 资源去重、已观测值与缺失覆盖 | response_id 优先；旧累计基线、跨未知归属、回退与零增量处理；缓存/推理不重复加总，字段覆盖单列 |
| 长周期基础重算、前期同类比较、最多三条引证建议 | 趋势重算交付/中位数/区间/质量/token；前期核对项目、来源、版本、窗口及覆盖；建议需 task/evidence 引用 |
| 只读来源、独立报告容器、Cadra/Cohestra 边界 | JSONL、Run/handoff 仅只读；README 不作旧状态证据；声明的未来 workflow 不导入；不调用 Cadra report |
| 可追溯 JSON 与 Markdown、历史更正和版本快照 | 快照 seal、输入哈希、报告自带 facts/ledger/corrections；更正只追加新版本，改写快照拒绝；重复生成统计一致 |
| 原生技能格式、包自包含、维护入口 | 原生 quick_validate.py、UI YAML、独立临时包校验、内部链接和 CLI 检查；双语 README 同步 |

## 审查发现与修复

以下问题均已修复，并有 [回归测试](test_relatra.py)。全面审查由 30 个用例增至 56 个，真实使用验收后增至 63 个。

| 级别 | 原问题 | 修复 |
|---|---|---|
| P1 | 旧 open turn 被推算为后续每一天都有活动，跨日交互重复计数 | 活动按明确观测/资源/完整区间确定；用户消息时间单列，交互仅计消息所在周期 |
| P1 | 多个范围修订重复计期末目标，共享人工介入等过程事件重复计数 | 最新修订计存量；全局过程事件稳定 id 去重，冲突拒绝 |
| P1 | 实现交付可只引用 agent 自述；周期起点没有证据字段 | basis、工具结果引用及已核对摘录；start_evidence/start_note；分类一致性检查，建议也需 evidence |
| P1 | 记录时间在截止前但 payload 时间在未来，当前 workflow 可污染旧报告 | 生命周期 cutoff 校验；工作流取最后可识别声明时间，未来文档不导入，未知时间需真实 dated anchor |
| P1 | facts 可被改写后继续报告，历史报告依赖原采集文件 | collect 保存 manifest 哈希；report 验证并保存自带 facts/corrections，原快照改写不影响既有报告 |
| P2 | 旧累计跨未知归属分配，零增量制造资源覆盖，未知 token 字段进入快照 | 归属检查点作为边界；弃用不可靠差值和零增量；只保存已定义的非负整数，缺口显式保留 |
| P2 | 嵌套子任务证据归属依赖遍历顺序；同一 turn 换项目不能正确关联 | 子孙引用扩展至稳定；保存 turn 触及的项目集合；fork owner 不明时不声称确认交互 |
| P2 | 畸形嵌套记录中断后续有效采集，生命周期冲突静默覆盖 | 逐项检查嵌套形状；损坏时间跳过并告警；冲突区间改未知，不选择最后一条凑时长 |
| P2 | Markdown 只显示交付/周期趋势，前期覆盖和来源不匹配仍可比较 | 补齐执行/质量/资源趋势、任务构成、验证层级和双方覆盖；不同来源、版本或覆盖不可推断改善 |
| P2 | 真实 plan_feedback 用户轮未确认，未知 trigger 可能静默漏记 | 计划反馈列入确认触发类型；未知类型保留候选交互 |
| P2 | 提问工具中的三次实际批答复被当普通工具输出，遗漏人工决策 | 配对提问与实际 answers，保留 user_feedback 引用；按答复分类介入，未分类答复显示覆盖缺口 |
| P2 | 已交付/已验收目标仍有 next_step，报告却写无遗留 | 显示非空未闭合后续行动；明确要求清空已经由其他目标完成的交接，不改变状态 |
| P3 | 日报出现没有数据的趋势表 | 仅在基础重算产生趋势时展示 |

## agent 使用验收与限制

两名独立 agent 分别使用技能处理真实 workflow 与 Relatra 历史；第三名 agent 先按原始日志封存目标/证据判断，再核对两份报告。发现的问题已修复并重新采集、审定。结果、证据路径及独立性限制见 [真实使用验收记录](relatra-forward-acceptance.md)。真实 smoke 仍仅证明采集链路，不替代语义验收。

本次真实样本覆盖同聊天多目标、计划/实施归并、共享 turn、实际咨询交付、同修订审查整改、限定规则层用户验收、工具答复以及截止后的验收隔离。跨聊天同目标、无父关联业务子 agent、跨周验收等仍仅有离线用例，不能宣称全部真实场景验收通过。核对具体成果和证据摘录，不只看数值输出。

已知范围：只读本地日志及可核实的 Run/handoff；远程、删除和未识别格式不保证完整。工具引用必须读实际源行后去敏，无法读取时保持待确认。不能将静态核对、构建、运行时与用户验收互换。未知日期不猜，不以当前文档回填旧周期；旧快照缺 seal 或新必需字段时重新采集。调度、提交、发布、费用、节省人工时间和模型排名均不在本版范围内。
