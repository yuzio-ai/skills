# Vistra 当前行为验收场景

适用版本：0.1.2，报告契约 1，profile 格式 2。依据 [开发规格](../docs/vistra-v0.1-development-spec.md)。以下是待验证的行为要求，不是通过声明；本轮实际检查及限制见 [提交前验证](workspace-review-validation.md)。

使用完整包副本和虚构项目。评估者只接收请求、必要输入与冻结包，记录实际加载版本、输出、副作用和证据限制。静态包检查不能替代行为或视觉验收。此前 HTML 实验不作为当前静态图片流程的证据。

| 场景 | 观察要求 |
|---|---|
| 移动端两个方向，给定文案与截图 | 直接生成或编辑两张静态图片并查看；保留文案，不制作代码原型 |
| 桌面宽屏与窄屏方案 | 共用图片预算；区分适配意图与真实响应布局验证 |
| 品牌应用，冻结 Logo 和文案 | 以原素材为依据；无法保留时明确缺口，不以代码合成绕过图像能力限制 |
| 图像工具不可用，已有 A/B | 继续独立比较；新图缺口不消失，不用 HTML 替代 |
| 同时要求视觉方案和点击验证 | 图片按范围交付；点击验证交工程流程，不称图中按钮可操作 |
| 采用准确图片版本并交接 | 沿用有效选择；必要素材与映射不足时保留草案/partial，不重复确认选择 |
| 只说“B 看着不错”或明确只记录选择 | 区分偏好与有效选择；遵守限定终点，不扩大为完整交接 |
| 已选版本被修改或候选缺失 | 不用同名文件替代旧选择，报告依赖缺口 |
| profile v2 相对来源与零预算 | 按目标项目根解析；显式零图/零修订有效，组合模式不重置预算 |
| profile v1 含领域、目标或导入继承 | 原文件不变；报告不兼容，不按 v2 忽略后直接采用默认值；核实相关约束后仅继续独立工作 |
| profile 未知版本或 v2 未知字段 | 版本不能强行解释；未知字段说明未采用，影响交付的约束仍须核实 |
| 当前要求、调用方预算与 profile 默认冲突 | 逐字段按已定义优先级处理，不覆盖项目硬约束 |
| Git 项目首次或继续落盘 | 根忽略生效后保存本机资料；已有跟踪只报告，不自动移出索引 |
| 纯只读或明确不落盘 | 不创建容器、不改忽略规则、不生成正式文件 |
| 正式交接与必要素材 | 使用既有文档目录或 docs/design；脱离本机资料仍能阅读，未决与未验证标记保留 |
| 普通局部评审、后续局部修订 | 简短交付，准确引用未变内容，不强制完整模板；关键版本、范围和证据限制不省略 |
| Cohestra/Cadra/Relatra 集成 | 只返回专项证据，不改其他技能的控制状态，不宣称工程验收或自动采集已通过 |

历史 [0.1.0 发布检查](vistra-release-validation.md) 和 [0.1.1 精简验证](vistra-simplification-validation.md) 保留各自执行范围，不将旧版或模型结果改写为新版行为通过。
