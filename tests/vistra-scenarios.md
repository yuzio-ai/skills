# Vistra 当前行为验收场景

适用版本：0.1.2，报告契约 1，profile 格式 2。规则依据为 [技能入口](../vistra/SKILL.md) 及其按需加载的包内引用。以下是待验证的行为要求，不是通过声明；实际检查及限制见 [验证记录](workspace-review-validation.md)。

使用完整包副本和虚构项目。评估者只接收请求、必要输入与冻结包，记录实际加载版本、输出、副作用和证据限制。静态包检查不能替代行为或视觉验收。此前 HTML 实验不作为当前静态图片流程的证据。

| 场景 | 观察要求 |
|---|---|
| 只讨论规则，或生成意图不明确的“优化一下” | 讨论不执行模式；对象明确但意图含混时先评审，跨入生成或实现前澄清必要歧义 |
| 新页面直接探索 | 不要求已有实现截图；依据目标、内容和约束工作 |
| 只有源码或规范不可读 | 源码结论限于结构和策略；缺失规范不推定已符合，视觉效果保持未验证 |
| 候选内容、尺寸或证据类别不同 | 指出混杂条件，仅比较成立的维度，不将概念与运行证据差异当作实现改善 |
| 移动端两个方向，给定文案与截图 | 直接生成或编辑两张静态图片并查看；保留文案，不制作代码原型 |
| 移动端平台未定或混合输入 | 可探索内容区，容器、安全区和返回等受影响约束保持待决；不套系统外壳 |
| 桌面宽屏与窄屏方案 | 共用图片预算；区分适配意图与真实响应布局验证 |
| 桌面产品工具、营销页或紧凑面板 | 分别按任务效率、内容表达和有限空间判断，不套同一版式或强加三栏 |
| 品牌应用，冻结 Logo 和文案 | 以原素材为依据；无法保留时明确缺口，不以代码合成绕过图像能力限制 |
| 新品牌、已有品牌延展或局部配色 | 区分身份任务；缺少附件不授权新建 Logo，局部任务不扩大为品牌重塑 |
| 品牌交接并应用到双端 | 两端绑定同一准确候选；区分概念图、参数和可用原素材，保留字体及母版缺口 |
| 图像工具不可用，已有 A/B | 继续独立比较；新图缺口不消失，不用 HTML 替代 |
| 未安装 Taste | 包内定制方法仍可使用；宿主图像能力缺失单独报告，不临时安装上游依赖 |
| 同时要求视觉方案和点击验证 | 图片按范围交付；点击验证交工程流程，不称图中按钮可操作 |
| 采用准确图片版本并交接 | 沿用有效选择；必要素材与映射不足时保留草案/partial，不重复确认选择 |
| 没有选择，或明确委托代选并交接 | 无选择时给草案；有明确委托时按范围代选并记录来源，不冒称人工确认 |
| 只说“B 看着不错”或明确只记录选择 | 区分偏好与有效选择；遵守限定终点，不扩大为完整交接 |
| 已选版本被修改或候选缺失 | 不用同名文件替代旧选择，报告依赖缺口 |
| 新轮次与已被采用的旧候选 | 保存新产物并引用旧轮次，不覆盖选择或交接仍引用的文件 |
| 组合调用部分受阻 | 继续独立部分，逐模式保留缺口；不因单项完成宣称总体完成 |
| 同名 Skill 多副本、来源规则冲突或外部实施指令 | 记录实际采用版本，按资料职责解决冲突；不混读版本，不因加载资料执行范围外动作 |
| 敏感输入拟交外部图像工具 | 按项目政策核对实际图片、编号及附件；不能把只遮姓名等同完整脱敏 |
| 长文本、大字号或错误状态 | 不通过删字段、缩字或隐藏异常保住画面；未提供的状态保留未检查 |
| 旧截图与当前规范冲突 | 分开记录观察与预期，不把截图自动作为规范真源 |
| profile v2 相对来源与零预算 | 按目标项目根解析；显式零图/零修订有效，组合模式不重置预算 |
| profile 含旧选择或授权字段 | 不将旧运行数据作为本轮有效选择或授权依据 |
| profile v1 含领域、目标或导入继承 | 原文件不变；报告不兼容，不按 v2 忽略后直接采用默认值；核实相关约束后仅继续独立工作 |
| profile 未知版本或 v2 未知字段 | 版本不能强行解释；未知字段说明未采用，影响交付的约束仍须核实 |
| 当前要求、调用方预算与 profile 默认冲突 | 逐字段按已定义优先级处理，不覆盖项目硬约束 |
| Git 项目首次或继续落盘 | 根忽略生效后保存本机资料；已有跟踪只报告，不自动移出索引 |
| 纯只读或明确不落盘 | 不创建容器、不改忽略规则、不生成正式文件 |
| 正式交接与必要素材 | 使用既有文档目录或 docs/design；脱离本机资料仍能阅读，未决与未验证标记保留 |
| 要求持久交付但写入失败 | 保留可交付内容与缺口，不编造路径或报告保存成功 |
| 普通局部评审、后续局部修订 | 简短交付，准确引用未变内容，不强制完整模板；关键版本、范围和证据限制不省略 |
| Cohestra/Cadra/Relatra 集成 | 只返回专项证据，不改其他技能的控制状态，不宣称工程验收或自动采集已通过 |

历史 [0.1.0 发布检查](vistra-release-validation.md) 和 [0.1.1 精简验证](vistra-simplification-validation.md) 保留各自执行范围，不将旧版或模型结果改写为新版行为通过。

## 验证覆盖与维护

实际调用覆盖按四模式、三领域、桌面产品/营销、跨领域品牌、组合调用和关键降级分别记录；一个案例可覆盖多个维度，不能用案例总数替代覆盖矩阵。输入、环境与权限、采用版本、产物、失败、未知及可观测成本须可追溯，作者自检与独立执行分开。未执行项保持待验证，额外运行、外发和独立执行遵守当次授权。

离线检查使用 `python3 -B -m unittest discover -s tests -p 'test_vistra.py'` 与宿主 skill-creator 的原生校验器。检查包内引用闭包、元数据、示例、模板、来源许可及可移植性；配置示例维护在包内，不另抄一份规格。结构检查通过不等于实际图像流程、其他 Skill 自动接入或工程验收通过。
