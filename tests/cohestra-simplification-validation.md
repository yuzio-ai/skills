# Cohestra 四项精简验证

日期：2026-10-22，Asia/Shanghai。发行版保持 0.10.1，协议保持 v0.8。

## 改动与边界

- 公共授权、候选、证据、复审和停止规则集中维护，阶段说明保留特有职责与交付要求。
- 任务索引正文不再另设当前阶段、当前候选、下一阶段字段；工作项按实际结果、明确要求或缺口记录。
- Handoff 保留五节，允许引用未变上下文、略去不适用字段，移除临时索引同步状态；仅登记实际执行的 verify。
- [发布细则](../cohestra/references/publication.md)集中维护校验、并发保护、原子发布、回读与失败恢复，不新增运行工具或依赖。

基线为本次开始时的工作区内容，包含此前未提交修改；不是 Git HEAD。未升级安装副本、迁移任务、提交或发布。历史验证记录未改写。

## 静态核对

- 契约字段定义及必填规则、任务索引 Front Matter 模板、next 映射表、unattended 语义和 release.json 与本轮基线逐项一致。
- Cohestra/Cadra 契约及规则静态检查通过；首次核对覆盖两包 36 份 Markdown、154 条相对链接，断链为 0。
- `test_project_data_paths.py` 的 2 项测试、`test_local_storage.py` 的 3 项测试通过；Cohestra 的 `git diff --check` 通过。
- 系统与内置 Python 缺少可用 PyYAML，原生 quick validator 未完成。改用已有 Ruby Psych 解析并检查技能元数据，另查 Markdown 围栏和未完成占位标记，均通过；未安装依赖。
- Markdown Unicode 字符总量由 37,800 降至 34,617，减少 8.4%，包含新增发布细则；SKILL.md 从 3,731 降至 2,551，减少 31.6%。这是文本体积比较，不是 token、耗时或执行效率测量。

## 实际调用

三个独立评估上下文使用修改后技能快照，只接收原始请求、项目材料和必要测试接口。共完成 14 次调用。两次模型容量中断后从现有进度恢复，没有重跑已完成阶段。各批内案例共享评估上下文，不声称 14 个全新会话。

| 调用 | 实际观察 | 核对 |
|---|---|---|
| code 两轮 | 首轮修改指定文案；次轮引用首轮上下文并记录用户修订；候选清单、局部检查和两轮交付保留；未自动进入 review | 通过 |
| review | 发现空列表除零问题，登记 R-001、blocking=1，推荐 fix；业务候选哈希未变 | 通过 |
| report | 展示 5 个任务及延期、待复审、未知和计数冲突；保留跨任务同名 finding；未将已关闭或否决项重新列为遗留 | 通过 |
| case-01 | 验收通过且完成字段联合同步 | 通过 |
| case-29、30、31 | 分别触发替换权限失败、并发修改、发布后回读失败；保留交付物并报告同步失败；回读失败后即使看到新版也不宣称同步成功 | 通过 |

发布用例由现有[夹具](cohestra-validate-fixture.py)提供原始输入和故障接口，执行者自行判断语义；现有[只读核对器](cohestra-validate-check.py)检查实际产物，结果为 **10/10，0 失败、0 未执行**。这是从原 46 例中选择的相关用例，未声称全套重跑。

report 调用前后比较路径、类型、权限、大小、inode、mtime、ctime 和文件内容摘要，完整快照一致。普通场景额外核对两轮候选及轮次、历史引用、review 候选只读和阶段边界。上述调用结束后的技能快照与最终仓库源逐文件一致。

## 证据与限制

[本轮完整证据](cohestra-simplification-evidence.json)保存修改前后技能文本、实际请求与产物、最终回复、候选检查、校验/发布事件、核对结果、report 前后快照和所用夹具源码。临时路径保留为原始事实，证据内容已内嵌，不依赖临时目录长期存在。

本轮验证覆盖受控简单业务候选和指定文件故障，不证明任意业务项目或全部并发时序。发布仍由智能体按规则使用工具完成，没有新增程序级事务锁。
