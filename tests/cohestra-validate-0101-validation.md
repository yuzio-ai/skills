## 修复

[公共流程](../cohestra/references/workflow.md)现在要求：

- 校验、检查结果、发布串行执行。必须先收到并确认成功结果，再用后续工具调用写入和发布。
- 非零退出、缺依赖、空输出或无法确认成功时，不继续依赖该校验的写入和发布。后续日志成功或外层退出 0 不抵消子检查失败。
- 有现成可用解析器时，先用另一独立调用完成完整校验，再发布。事后补验不能追认此前违规发布成功。
- 校验与完整待发布内容的路径、字节摘要、本轮阶段/轮次和候选绑定。内容改变后必须重新校验。

入口 [SKILL.md](../cohestra/SKILL.md)同步指出该关口。版本改为 0.10.1，根双语导读同步；没有给技能加入脚本运行时。

## 备用解析器夹具修正

首轮 case-45 的驱动无论选择哪种解析器，第一次都返回缺模块错误。执行者先选 Ruby、再选 Python，两次均失败后安全停止，没有违规发布，但这不能检验“已有可用备用解析器”的恢复路径。首轮结果为 45 个符合预期、1 个未覆盖恢复路径。

夹具修正为 Python 适配器持续返回真实缺模块错误、Ruby 适配器实际可用；原始请求明确先用 Python，备用 Ruby 已具备且获准使用。没有向执行者提供预期任务状态、作者结论或核对表。新上下文执行者完成失败→切换→完整校验成功→发布。最终按每个逻辑用例的最后一次有效执行汇总 46/46；不是声称首次 46 次都符合原先预期。两轮原始记录均保存。

首轮 3 个独立上下文分别处理 01～16、17～32、33～46，另 1 个新上下文只处理 45。每例为独立项目，但多个用例共享同批执行者上下文；不是 47 个独立会话。[0.10.0 的失败记录](cohestra-validate-validation.md)继续保留，不以本轮结果改写历史。
