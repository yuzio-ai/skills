# Relatra 独立真实使用验收

日期：2026-10-13，Asia/Shanghai。范围：冻结的本项目历史日志、技能使用、目标账本及报告证据判断。没有执行源业务任务，未提交、发布或安装技能。

## 方法与独立性

两名 evaluator 只收到真实报告请求、技能目录、各自最小原始日志及独立临时输出目录。初次执行不提供预期目标数、缺陷或修复建议。第三名 auditor 只读原始日志，先封存目标/证据基线，再读取 evaluator 的报告。初次产物与基线保持原样，定向修复后的复验另存新快照和报告。

Workflow evaluator 初次误读了 memory 注册索引的技能条目标题/摘要，随后停止；未读历史验收结论或对应 rollout。该轮不能称完全盲测。Relatra evaluator 与 auditor 未读 memory 或既有测试结论；auditor 对两场景独立核读原始证据。复验允许明确告知已经发现的缺陷，不称新的盲测。

原始证据保存在执行者本地隔离目录，不随仓库分发。四份日志副本与原文件冻结字节前缀的 SHA256 均未变；当前活跃日志在冻结范围外可继续追加。来源范围、字节数及哈希保存在本地 `sources.json`。公开记录仅保留脱敏判断、统计和结果哈希，不提供仅本机可用的路径链接。

## 真实判断覆盖

| 场景 | 验收依据与边界 |
|---|---|
| 同聊天多个目标 | Relatra 方案/命名、实现、全面审查分别成立；命名反馈属于原设计目标 |
| 计划与实施归并 | Workflow 账本把计划纳入实施目标，实际变化仍完整；不机械要求计划另计一次交付 |
| 共享轮次与整改 | 审查和实现可共享一个 turn；任务级时间/token 保持未知，总体去重；同修订首次交付不因整改重复计算 |
| 咨询及审查交付 | 实际答案可证明该类目标交付；实现必须核读原始工具产物，不能仅凭 final/task_complete |
| 验收条件 | 用户认可方案不等于认可技能实现；Workflow 的 47/47 用户反馈仅接受规则层，未称阶段联调通过 |
| 版本范围 | 用户已提供的 v0.4 主规则不冒领为本轮新增；报告仅计实际补齐的规则边界 |
| 用户答复 | 四份实际工具批答复逐项核读，补入其中三次遗漏决策；每批计一个方向决策，未分类答复显示介入统计缺口 |
| 等待 | 同步输入请求到实际答复可记录 input wait，含工具传递；不换算人工投入，也不从轮次执行时间盲扣 |
| 截止隔离 | Relatra 截止为历史最后业务结束后一秒；本轮真实验收在截止之后，不回填旧目标状态 |
| guardian 来源 | Workflow 第三份来源只有三行 guardian 元数据，无业务轮次或资源；不作为继承历史去重的真实证明 |

## 发现与整改

- 确认交互漏计 plan_feedback，修复后 Relatra 为 4 个已确认用户轮。未知 trigger 留候选，不凑确认。
- 已交付/已验收目标仍有未闭合后续，却被报告写成无遗留。修复展示；审定账本清空已完成交接，保留实际未闭合验收。
- 三次工具用户决策未进入介入账本。采集器保留配对的 user_feedback 引用与 request_location；agent 分类，脚本报告未分类覆盖。
- 日报空趋势表已移除。
- 证据分类更明确：实际执行的离线 Python 单测为有限 runtime；原生格式、AST/链接为 static；缺依赖导致校验未执行为前提失败，不认定技能格式失败。以上都不等于完整 agent 使用验收。

## 验收结果与证据

两场景重新采集、审定并生成两次报告。auditor 对修复后的目标与证据语义复核通过，未发现新增错误。主 agent 从新报告自带的 facts/ledger 重新计算统计和 Markdown，与保存产物一致；每场景两次报告字节一致。

## 适用限制

本次仅验收两个真实历史样本和可读取冻结范围。不能推断目标拆分或证据判断在任意历史中始终正确。跨聊天同目标、无父关联业务子 agent、跨周验收、未知或截断工具答复仍不具备本轮真实样本证据。远程、已删除历史及未知格式的完整性未知。

临时原始产物用于本机复算，可能随临时目录清理失效；本文件保留验收口径和结果，不将敏感原始日志作为可发布测试 fixture。
