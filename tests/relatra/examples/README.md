# 周期报告阅读样例

以下均为合成数据，用于检查阅读结构，不是实际项目成果或真实运行验收。日、周、月使用同一组五个目标及事件，按各自窗口重算；摘要由人工按周期组织，不由脚本推断优先级。

| 周期 | 重点正文 | 完整明细 | 本期交付数 |
|---|---|---|---|
| 日报 | [正文](daily/report.md) | [明细](daily/details.md) | 1 |
| 周报 | [正文](weekly/report.md) | [明细](weekly/details.md) | 2 |
| 月报 | [正文](monthly/report.md) | [明细](monthly/details.md) | 3 |

日报聚焦导航调整，周报将体重与导航入口归为操作入口进展，月报归纳恢复保护和操作入口两个阶段成果。网站发布需要用户决定，放在成果之前；构建通过未表述为真机验证或发布。旧版说明不属于本期成果；跨期的恢复验证遗留仍完整展示。

输入与生成器：[report_fixture.py](../report_fixture.py)。在仓库根执行 `python3 -B tests/relatra/report_fixture.py` 可重建这六份 Markdown；自动化测试核对其可复现性、窗口计数和正文任务链接。示例 `/work/example-*` 是虚构项目路径，链接内的证据标识对应合成账本，不提供真实源文件。

人工阅读核对：栏目顺序、日周月归纳层级、关键限制、用户决策项及下一步原因。合成测试不证明真实日志的目标拆分或证据语义判断正确。
