# Relatra 当前验收场景

适用版本：0.3.0，schema v2。以下为当前验收要求，不是通过声明。规则依据为 [技能入口](../../relatra/SKILL.md)、[数据与调用](../../relatra/references/data.md)、[报告写作](../../relatra/references/reporting.md)及[统计口径](../../relatra/references/metrics.md)。

## 基础场景

| 场景 | 核对要求 |
|---|---|
| 独立技能、Codex 优先、个人复盘、明确项目集合 | [SKILL.md](../../relatra/SKILL.md)、[UI 元数据](../../relatra/agents/openai.yaml)、configure；保留后续适配器接口及本地覆盖限制 |
| 日/周/月/季/年/自定义，中文、上海时区，默认上一完整周期 | period_window；自然周期、DST、闰年、自定义及阶段性测试 |
| 目标为任务，单聊天多目标、跨聊天归并、子 agent 合并 | 候选交由 agent 判断；稳定 id/revision、turn/root 引用、共享资源未知、嵌套子任务及多项目测试 |
| 交付与验收分开，成果具有目标/变化/证据/限制/下一步 | 事件 basis 与验证分类、源引用/去敏摘录；实现自述不算交付，实际咨询答案可交付；起点也需证据 |
| 流量、期末状态、重开、范围修订、失败历史 | 首次交付按修订计数；最新修订计目标存量；重开不新增同修订交付，旧版本和失败记录保留 |
| 完成周期、执行时长、并发占用、交互和等待 | 基础区间裁剪、并集、中位数附样本；交互按用户消息时间，历史 open turn 不推算执行活动 |
| 返工、重试、范围调整、验证、人工介入分类 | 稳定过程事件 id 去重及冲突拒绝；验证类别校验；未记录不解释为未发生 |
| 资源去重、已观测值与缺失覆盖 | response_id 优先；旧累计基线、跨未知归属、回退与零增量处理；缓存/推理不重复加总，字段覆盖单列 |
| 长周期基础重算、前期同类比较、最多三条引证建议 | 趋势重算交付/中位数/区间/质量/token；前期核对项目、来源、版本、窗口及覆盖；建议需 task/evidence 引用 |
| 只读来源、独立报告容器、Cadra/Cohestra 边界 | JSONL、Run/handoff 仅只读；README 不作旧状态证据；声明的未来 workflow 不导入；不调用 Cadra report |
| 可追溯 JSON 与 Markdown、历史更正和版本快照 | 快照 seal、输入哈希、报告自带 facts/ledger/corrections；更正只追加新版本，改写快照拒绝；重复生成统计一致 |
| 原生技能格式、包自包含、维护入口 | 原生 quick_validate.py、UI YAML、独立临时包校验、内部链接和 CLI 检查；双语 README 同步 |

## 复用、模式与回归边界

| 场景 | 预期 |
|---|---|
| 普通与深度模式 | 成果、状态和资源口径一致；普通模式不要求过程分类，未统计不写为零；周期长短不触发深度模式 |
| 已核实旧目标没有新活动 | 复用账本，不重复核读或计为本期新成果；未闭合后续仍展示 |
| 同聊天新轮次仍带旧候选 ID | 新活动交由 agent 判断，不自动吸收进已完成目标 |
| 来源、证据或子任务发生变化 | 进入 review_queue，保留历史并清除失效确认；来源缺失时保留目标和覆盖缺口 |
| 深度模式复用已有报告 | 本期过程证据重新复核，process_reviewed 不继承；未完成时报告缺口 |
| 自动选择前期报告 | 先按有效截止再按修订选择；畸形 manifest 保留诊断并继续查找 |
| 指定报告无效、范围或时区不同、截止在未来 | 拒绝不适用复用，不以错误基线计算变化 |
| 旧 open turn、跨日用户交互 | 不推算后续每日执行活动；用户交互只计消息所在周期 |
| 多次范围修订、共享过程事件 | 最新修订计期末目标存量；事件按稳定 ID 去重，冲突拒绝，不按目标重复计数 |
| 实现交付只引用 agent 自述 | 不作为交付证明；核读工具证据及去敏摘录，明确验证类别；咨询答案本身可以构成交付 |
| 周期起点没有证据、未知日期或状态 | 不猜测完成周期，不用当前状态补造历史；建议引用对应目标和证据 |
| payload 在未来、当前工作流回填旧报告 | cutoff 隔离；生命周期冲突保持未知，无可靠日期锚点时不导入旧周期 |
| facts、ledger 或快照被改写 | 哈希核对失败；既有报告保留独立数据，不依赖外部可变文件 |
| 更正、拆分或合并历史目标 | 完整账本更正，必须有父版本与理由且周期一致；追加新版本，原版保留，统计可复算 |
| 旧累计跨未知归属、回退或零增量 | 不从不可靠差值分配资源，不制造资源覆盖；未知字段不导入账户元数据 |
| 嵌套子任务或同一 turn 涉及多项目 | 引用扩展不依赖遍历顺序，保存项目集合；fork owner 不明时不声称确认交互 |
| 截断日志、损坏嵌套记录、非法时间或 token | 保留有效记录和覆盖缺口；只接受已定义的非负 token 整数，不因单条畸形中断后续采集 |
| 比较来源、版本、字段覆盖或诊断不匹配 | 仅并列观察值，不推断效率改善；固定范围提示不掩盖新增读取错误 |
| 计划反馈、提问工具批量答复 | 按已配对的实际用户反馈识别；未配对或其他工具输出不算人工反馈；未分类项展示覆盖缺口 |
| 未知触发类型 | 保留候选交互，不静默遗漏用户消息 |
| 已交付或验收目标仍有 next_step | 展示未闭合后续，不自动写成无遗留 |
| 普通报告无基线、无建议或日报无趋势 | 省略空章节，保留影响判断的限制，详细过程保留在 JSON |
| 重点正文与完整可读明细 | 正文突出概况、需你处理、成果、遗留及下一步；完整任务、事件、限制、后续行动和适用统计保留在 details.md，JSON 继续保留 |
| 同账本日、周、月归纳 | 日报看当日推进，周报按目标归纳，月报看阶段成果与差距；窗口独立重算，历史成果不计作新交付，关键限制跟随正文成果 |
| 多项目及大量任务 | 正文重点由 agent 依据账本整理，不按数量或耗时选优；明细不截断，每项有按 id/revision 稳定的唯一锚点 |
| 缺少摘要、无成果和旧文本摘要 | 缺摘要明确提示并提供概览与明细，不自动选择重点；空周期不猜资源为零；普通文本 summary 仍可生成 |
| 未知、字段覆盖不足及阶段性报告 | 正文标明阶段性；时间及总 token 按各自覆盖标记部分观测值，未知不补零；采集或归属缺口提示留在正文，数字和诊断在明细 |
| 正式交付与历史更正 | 正文与明细同时保存，改名同步更新相对链接并保留锚点；更正仍新增版本，既有报告及源日志不变，不给旧版补写明细 |
| 当前结论、历史事件与重复遗留 | 当前结论、限制、未闭合行动置于历史之前；agent 依据后续证据关闭过时限制和重复待办，保留 ID、修订、事件与交付时间，脚本不从文字自动推断状态 |
| 统计周期与已发现活动 | 按本期未排除轮次的活动和明确区间计算首末日期，区分周期、实际截止和阶段性；空记录未知、跨期裁剪、未知时间、多项目及排除轮次不冒充连续完整覆盖 |
| 可读数字与精确资源 | 正文时间、token 舍入时标约，缓存输入独立未知且不重复加总；明细保留时分秒、原始秒数与精确分隔数字，JSON 及各项统计不变 |
| 输出与源日志、其他工作流容器重叠 | 拒绝写入，覆盖符号链接绕入；允许 Relatra 容器及独立自定义目录 |
| 旧 schema 或旧 patch 接口 | 旧文件保持可读；不自动迁移或沿旧接口复算，需重新配置与采集 |
| 隔离完整技能包调用 | 配置、首次采集、复用、深度模式、报告和更正链路可执行；仅依赖 Python 3.9+ 标准库 |

## 验证入口与边界

离线回归：`python3 -B -m unittest discover -s tests/relatra -t tests -p 'test_*.py'`。测试使用合成输入，包含隔离包调用；[日、周、月阅读样例](examples/README.md)用于核对正文与明细，不作为真实项目交付证据。最低运行版本需用 Python 3.9 实际执行。技能格式使用宿主 skill-creator 的原生 `scripts/quick_validate.py` 检查，校验环境的 PyYAML 不属于 Relatra 运行依赖。

真实使用验收需另行核对目标拆分、跨聊天归并、证据语义、跨周期验收及来源覆盖。离线通过不证明任意真实历史均可正确解释。远程、已删除与未识别来源的完整性保持未知。工具引用必须核读实际源行后去敏，无法读取时保持待确认；不将静态、构建、运行时和用户验收混用。调度、源任务执行、提交、发布、费用、节省人工时间和模型排名不在范围内。
