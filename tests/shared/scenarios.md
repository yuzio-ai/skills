# 本机资料与正式文档场景

以下为技能行为验收场景，不表示已完成真实 agent 或迁移器实测。Git 语义由 `test_local_storage.py` 单独验证。

| 场景 | 预期 |
|---|---|
| 首次写入、已有容器继续写入 | 检查并最小维护根 `/.yuzio/`，不重复添加、不覆盖其他规则；检查实际生效 |
| 安装、只讨论、Cohestra report、Cadra list、Vistra 只读 | 不建目录、不修改 `.gitignore` |
| 已跟踪资料或项目显式反向规则 | 区分两者：已跟踪只报告且不自动移出索引；显式跟踪冲突不偷偷覆盖或声称已忽略 |
| 根 `.yuzio` 与嵌套测试夹具同名 | 根本机资料不进入暂存；夹具和正式文档仍可进入 Git |
| need/design/validate 普通阶段交付 | handoff 留本机，不把每一轮过程记录复制成正式文档 |
| 任务要求正式需求、设计、验收或执行报告 | 沿用项目文档目录；无约定落 `docs/`；结论及必要附件可脱离本机资料阅读 |
| 只要求修订接口，项目规范要求同步接口文档 | 自动更新既有接口文档，不等用户补说“写文档”，不另建重复说明 |
| 要求形成给开发实施的设计，没有指定保存位置 | 自动整理设计说明与必要素材到既有文档目录或默认目录，不询问是否归档 |
| 项目规范要求保留批次执行总结，用户仅调用 Cadra report | 自动整理正式执行总结，原 Run 结果与 checkpoint 不变 |
| Relatra 任务用于团队周报，已有项目报告规范 | 自动形成正式报告，无需追加归档指令；个人复盘仍默认留本机 |
| need/design/review/validate 限制业务候选只读，但本阶段需要正式说明/报告 | 按职责自动整理文档，不修改被核对的候选或验收要求 |
| 正式设计交付尚有未决参数，项目要求保存草案 | 自动保存可交付草案并标明未决，不因归档要求代选方向 |
| 目录和附件位置可从规范确定 | 直接沿用并补齐，不单为是否整理、路径或附件重复确认 |
| 明确只讨论、不落盘，或使用 Cohestra report / Cadra list 纯只读入口 | 自动整理规则不扩展输出范围，不写正式文档 |
| 正式文档只引用本机图片或原始日志 | 补必要共享附件/证据摘要或报告持久交付缺口，不把失效链接当完成 |
| Cadra checkpoint 未闭合或 Run 写入中断 | 按既有 resume 规则核对补齐，不伪造成功 |
| Cadra 中断后继续 | 原 run-id、轮次、call id、授权消费、调用预算和整改轮保留；不重跑已交付阶段 |
| 来源 Run 结果为 blocked/failed 的任务 | 按 run 显式恢复进入新 Run，不用 resume 重开旧终态 |
| Vistra 继续已选候选 | 核对准确版本、选择范围及已消费预算，不凭 A/B 简称恢复，不重新生成已交付图片 |

验证边界：静态链接与技能校验只证明包可读取，临时 Git 测试只证明存储语义；任务接续和中断恢复仍需在实际调用中执行并核实。

## 验证入口

`python3 -B -m unittest discover -s tests/shared -t tests -p 'test_local_storage.py'` 验证 Git 存储语义；`python3 -B -m unittest discover -s tests/shared -t tests -p 'test_project_data_paths.py'` 检查维护路径及链接检查器。行为场景需另行实际调用验证。
